# 最近添加虚拟歌单（A5）

> 落地日：2026-10-31（Asia/Shanghai）
> 版本：随下一 patch 发版（实现提交在前，versionCode 由 `scripts/release.sh` 抬）

## 干了什么

曲库 **歌单** 视图与车机媒体浏览树新增固定入口 **「最近添加」**：

- 按歌曲字段 `dateAdded` **倒序**（MediaStore `DATE_ADDED` / 本地扫描 `lastModified` / 在线歌单 `updatedAt`）
- 最多 **100** 首，与「最近播放 / 最常播放」同一上限
- `dateAdded == 0`（未知入库时间）**不进列表**
- 只读虚拟列表：不可重命名 / 删除 / 拖序（与其它虚拟歌单相同）
- 封面走既有四宫格规则（前 4 首）

**不是**「最近播放」：后者看 `song_state.lastPlayedAt`；本入口看入库时间。

## 怎么干的

1. `VirtualPlaylist.RECENTLY_ADDED = -4L` + `LibraryUiState.extraRecentlyAdded`。
2. 纯函数 `recentlyAddedSongs(songs, limit=100)`（`state/UiState.kt`）：过滤、排序、截断；`PlaylistStore.refreshPlaylistsNow` 与单测共用。
3. `virtualPlaylistInfo` / `PlaylistStore.openPlaylist` / `M3uStore` 导出路径 / `LibraryCore.applyRemovedFromMemory` 全接线。
4. 歌单列表 UI（`LibraryLists`）插在「最近播放」与「最常播放」之间。
5. 车机：`BrowseIds.RECENTLY_ADDED = "wt:vpl:added"`；`SongDao.recentlyAddedIds`；`LibraryBrowseStore` / `LibraryBrowser` 根节点第四个虚拟项。
6. 单测：`RecentlyAddedSongsTest`、`VirtualPlaylistInfoTest` 补分支、`LibraryBrowserTest` 根节点改四项 + 排序用例。

未改 G5/G6（睡眠自定义 / 歌词常亮）相关文件；与并行的收藏磁贴 / 睡眠再播 N 首错开文件面。

## 怎么验

1. 曲库 → 歌单：应看到「我的收藏 / 最近播放 / **最近添加** / 最常播放」再接用户歌单。
2. 打开「最近添加」：顺序应与刚扫描入库的新歌一致（新的在上）。
3. 车机 / Android Auto 浏览树根节点同样有「最近添加」。
4. 单测：
   ```
   ./gradlew :app:testDebugUnitTest --tests com.luckylearning.windtone.state.RecentlyAddedSongsTest
   ./gradlew :app:testDebugUnitTest --tests com.luckylearning.windtone.state.VirtualPlaylistInfoTest
   ./gradlew :app:testDebugUnitTest --tests com.luckylearning.windtone.playback.LibraryBrowserTest
   ```

## 不做

- 不做「最近 N 天」时间窗过滤；不做按专辑聚合的「最近添加专辑」
- 不改歌曲列表顶栏的「按添加时间」排序（那是另一条 SortOrder.DATE_ADDED 路径，早已存在）
- 不进启动器快捷方式（仍只有播放全部 / 随机 / 我的收藏）
