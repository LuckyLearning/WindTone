这一次重构解决什么

旧版功能与状态其实已经是「一套」（同一 PlayerUiState、同一 VM、同一 PlayerScreen）， 割裂发生在外壳组件、尺寸体系、形态判据、功能裁剪四层：三套互不相干的形态判定、三对各自独立自绘的组件、 6 套令牌来源、20+ 处 if (carMode)、以及旧视觉真源里 0 个双端并排对照屏。

v2 的目标不是把两端画成一样 —— 竖屏触摸与横屏远距驾驶的物理形态决定了布局必须不同。 目标是 同源组件 + 同一套令牌 + 功能对等 + 状态统一，差异只体现在密度与呈现态参数上。 本页每一屏都把手机与车机并排放置，差异与共用一眼可查。

1统一形态判据 UiFormFactor
1张 UiDensity 密度表覆盖全端
3→1三对独立壳组件合并为同源组件
6→2令牌来源收敛为主题层 + 视觉增强层
0→全部双端并排对照屏

05

功能对等

按形态启用，而不是从某一端整块删除
能力旧：手机旧：车机v2说明
长按多选 / 批量操作有整块删除两端开放车机改用大触控目标长按，不再禁用
排序 / 格式筛选 / ⋮ 工具 / 语音搜索有只剩搜索两端开放同一批动作，只调可见性与密度
±10s / ±15s 快进快退有删除两端开放车机改为大按钮，不与系统方控冲突
底部状态行 / 字母索引有删除两端开放车机放大字号而非删掉
≥56dp 触控 / 可见焦点环无有按形态手机横屏 / 外接旋钮时同样启用
场景芯片 / 悬浮窗侧钮 / 车机音效档案无有按形态能力开关，不再是车机专属分支
手势语义左右 = 切视图左右 = 切歌全端统一左右 = 切歌 / 上下 = 切视图
物理约束保留（真机乱码 / 崩溃级）：矢量图标绝对坐标、PlayerScreen 不加 navigationBarsPadding、 minSdk 24 禁 java.time、资源化 i18n 英文兜底、Song.stableKey 算法不变、默认值单一出处、 车机 Dock 56dp 让位、弹层 70% 限高。这些不是「历史包袱」，是系统/真机约束，v2 不推翻。
