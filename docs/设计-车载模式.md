# 车载模式重设计 · 单栏大控件

> 状态：**已落地** —— v1.1.19 起为单栏大控件（第一~十节），v1.1.32 起补上设置扁平化与「任何页一步回播放」（第十一节）。
> 本文是车机端的**现状依据**，改车机界面前先读它。
> 效果图见 [界面效果图 · 六、车机版](ui/06-car.html)（㊱B 主页 / ㊲B 播放页 / ㊵ 设置）。
> 前置背景：v1.1.14 因「车机 Dock 压住设置」+「用户明确不要双栏」，把 1.0.3 起的车机两栏界面整体下线，
> 车机从此与手机共用单栏。代价是**车载模式只剩三四个细节**，用户反馈「开关拨了感觉一样」——本文就是补回那段落差。

---

## 一、为什么现在"感觉一样"

| 项 | 代码位置 | 生效时机 | 手机上可见性 |
|---|---|---|---|
| 启动直进播放页 | `PlaybackEngine` 构造时 `playerExpanded = prefs.carMode` | **仅启动时读一次** | 拨开关当次无感，需杀进程重开 |
| 锁定横屏 | `MainActivity.onCreate` 读 `requestedOrientation` | **仅 onCreate** | 同上 |
| 歌词态 5 秒沉浸 | `PlayerScreen` `CAR_IMMERSIVE_DELAY_MS` | 实时 | 只在**歌词态**且要等 5 秒；封面态不收起 |
| 歌词字号 ×1.5 | `LyricsPane` `CAR_LYRIC_BOOST` | 实时 | 可见 |
| 内容限宽 760dp / 设置页 1100dp | `PlayerScreen` `CAR_CONTENT_MAX_WIDTH` | 实时 | 手机竖屏约 411dp，**永远触不到上限** |
| 开机自启 | `CarBootReceiver` | 开机 | 需重启设备才验证 |

结论：三个"实时"项里有两个在手机上看不出来，剩下一个要等 5 秒且必须在歌词态。**不是开关坏了，是差异被稀释了。**

两栏首页（`CarHomeScreen.kt`）是唯一"一眼就不同"的部分，已停用。

---

## 二、设计目标

1. **一眼可辨**：行驶中视线离开路面 1 秒内能认出「这是播放器、现在放的是哪首、下一个动作按哪」。
2. **一指点中**：所有可点区域 ≥ 76dp，主操作 ≥ 96dp；不依赖精度手势。
3. **少层级**：主要动作最多两级（首页 → 播放页）；不做需要"先展开再选"的导航。
4. **单栏到底**：不做左右分栏（v1.1.14 的用户否决仍然有效）。宽屏的余量用来**放大控件**，不是切分屏幕。
5. **开关有感知**：切换车载模式后**不需要重开应用**就能看到界面变化。

---

## 三、硬约束（来自真机）

| 约束 | 数值 | 影响 |
|---|---|---|
| 屏幕 | 2560×1600 px，16:10，12.8~13" → 约 1707×1067dp，hdpi(240) | 宽高比 1.6，纵向只有 1067dp |
| 车机 Dock | 底部固定按钮栏（Home / 应用 / 空调），**是车机自己画的浮层，`WindowInsets` 报 0** | 必须保底让出 56dp，否则左下角按钮点不到（v1.1.14 事故） |
| 操作方式 | 触摸（车机屏多为电阻/廉价电容）+ 方向盘按键 + 中控旋钮 | 需要**可见焦点**；滑动手势不可靠 |
| 视距 | 驾驶位到屏幕约 60~70cm | 字号比手机大一档；歌词要 ×1.5 |
| 使用场景 | 行车中，单次操作 ≤ 2 秒 | 不能有「长按」「拖动排序」「双指」这类动作 |

## 四、信息架构（单栏）

```
┌───────────────────────────────────────────────────────────────┐
│ 标题行 56dp   「本地音乐」 500 首        [搜索 76] [设置 76]  │
├───────────────────────────────────────────────────────────────┤
│ Tab 行 72dp   全部歌曲 │ 专辑 │ 歌手 │ 文件夹 │ 歌单      │  ← 横向平铺，高 64dp
├───────────────────────────────────────────────────────────────┤
│ 列表区（限宽 1280dp 居中）                                    │
│   行高 88dp：封面 64 │ 歌名 21sp / 歌手 15sp │ 时长 │ [⋮ 76]  │
│   ... 约 8 行可见 ...                                         │
├───────────────────────────────────────────────────────────────┤
│ 底部大播放条 112dp                                            │
│  封面 80 │ 歌名 22sp / 歌手 15sp │ ⏮ ▶ ⏭ (76/88) │ 进度 │ 歌词 │
├───────────────────────────────────────────────────────────────┤
│ 车机 Dock 保底 56dp（不进布局，只留白）                        │
└───────────────────────────────────────────────────────────────┘
```

### 为什么用横向 Tab 取代抽屉

抽屉要「点一下 → 再点一下」，两级且第二级目标位置会变。车机上把五个入口平铺成 Tab，**一步到位**。
六个入口放得下：1707dp 宽，每个 Tab 最小 180dp，5 个 = 900dp + 间距，余量充足。五个 Tab 就是 `LibraryView` 的五个枚举值（歌曲 / 专辑 / 歌手 / 文件夹 / 歌单），与手机抽屉共用同一状态，不新增视图。

设置不从 Tab 走，固定在标题行右侧（**唯一入口，不违反「入口收敛」**：同一目的地仍然只有一处）。

### 为什么列表还要限宽

1707dp 全宽铺满时，歌名与「⋮」按钮会相隔 1500dp，视线要扫过整个屏幕。限宽 1280dp 居中后，
一行仍比手机宽一倍多，但距离可控。**限宽只对内容，不对背景与播放条**——播放条横贯全宽是车机的正确做法（离手最近）。

## 六、交互规则

1. **触控目标**：所有可点元素 ≥ 76dp；主键 ≥ 96dp；相邻按钮间距 ≥ 24dp。
2. **焦点可见**：所有可点元素 `focusable` + `focusRequester` 顺序 = 视觉顺序（标题行 → Tab → 列表 → 播放条）；
   焦点态画 3dp primary 描边，**不用** Material 默认的涟漪代替可见焦点（车机旋钮不会产生触摸点）。
3. **手势禁令（仅车载模式）**：
   - 禁用「左右滑动切歌」——车机触摸板误触率极高，改为常驻 ⏮ / ⏭ 大按钮；
   - 禁用「长按多选」——改为行尾「⋮」面板里的「选择」；
   - 禁用「拖动排序」——面板里给「上移 / 下移」。
   非车载模式保持原样，不做全局替换。
4. **无键盘输入**：搜索按钮点开后是**全屏搜索页**（输入框置于顶部，字大、键盘弹出后列表仍可见），
   不做「最近搜索词」以外的联想。
5. **沉浸计时**：进入播放页 / 任意触摸 / 按返回 → 重置 5 秒；切到封面态计时暂停；离开播放页清零。
6. **退出**：播放页顶栏「收起」回首页；系统返回键在沉浸态先恢复界面（现有 `BackHandler` 逻辑保留）。

## 七、开关立即生效（修「感觉一样」的核心）

| 项 | 现在 | 改成 |
|---|---|---|
| 锁定横屏 | `onCreate` 读一次 | `MainScreen` 里 `LaunchedEffect(player.carMode)` → `activity.requestedOrientation = …`，开关一拨立刻转 |
| 直进播放页 | 构造 `PlaybackEngine` 时读一次 | `setCarMode(true)` 里同步 `playerExpanded = true`（立即展开播放页）；关闭时**不改当前页面**，只让下次启动回库页 |
| 文案 | 副标题「启动直进播放页 · 歌词自动收起 · 开机自启」 | 追加一句「切换后立即生效」（横屏会有一瞬间旋转，属预期） |

不做「自动重启 Activity」：会打断播放动画且时序难控；用 `LaunchedEffect` 直接改 `requestedOrientation` 即可，
系统会自行完成旋转，Activity 不重建（`configChanges` 已声明）。

## 十、明确不做

- **左导航 / 右内容的两栏**：v1.1.14 用户否决，本文不再提。
- **播放页左右分栏**（封面在左、控制在右）：同样属于分栏，且会打乱现有 `PlayerScreen` 复用。
- **车机侧搜索联想 / 语音入口**：不做空壳。
- **车机独立主题**：颜色令牌共用手机版。
- **横屏下的多列网格列表**：一行超宽的问题用限宽解决，改用网格会让「正在播放第几首」难判断。

## 十一、v1.1.32 · 设置扁平化 + 任何页一步回播放

> 效果图 [㊵ 车机 · 设置（扁平单页）](ui/06-car.html#scr-car-settings-flat) · 代码 `ui/CarSettingsScreen.kt`

### 11.1 依据：Google 车机设计规范的三条硬要求

| 要求 | 原文口径（Android for Cars / Driver Distraction Guidelines） | 改造前 | 改造后 |
|---|---|---|---|
| **层级要浅** | 非驾驶主任务应「打开即可操作」，避免多级导航；设置类最多两级 | 六卡 → 子页 → 弹层，**三层**；横屏上还要滚两屏 | 车载设置**一层**（就地改），「完整设置」是唯一的多级例外 |
| **控件要大** | 触控目标 ≥ 76dp、主操作 ≥ 88dp；不用需要精度的拖动 | 13sp 小字、Slider 拖动、Switch 32dp | 行高 ≥76dp、标题 22sp、Slider 换成 **− 值 +** 76dp 圆键 |
| **now playing 常在** | 任何画面都要能直接回到正在播放 | 设置盖上来后底部播放条被挡，回播放页要「返回 → 返回 → 点播放条」 | 车载设置底部**常驻播放条**（100dp），封面 / 歌名 / 「播放页」三处都一步直达 |

### 11.2 车载设置页保留什么

只保留**行车中真会改**的项，其余一律收进「完整设置（建议停车后调整）」：

- 播放：播放速度、变调、跳过静音、继续上次播放、开机后台播放
- 歌词：歌词字号、桌面悬浮歌词（未授权时直接说明缺哪项系统权限）
- 曲库：重新扫描、扫描范围
- 更新：当前版本、检查更新
- 更多：完整设置（均衡器 / 悬浮歌词外观 / 数据维护 / 下载线路）

故意**不放在**车载页上的：均衡器与音效（需要边听边调、多参数）、悬浮歌词的位置 / 宽度 / 颜色细调、
格式与容量统计、收听报告、重复清理、崩溃日志与调试分区、下载线路 —— 都属于「停车才做」。
这不是砍功能：它们全在「完整设置」里，路径与原手机版一致。

### 11.3 任何页一步回播放

| 所在页面 | 回播放页的路径 |
|---|---|
| 曲库（歌曲 / 专辑 / 歌手 / 文件夹 / 歌单） | 底部大播放条 → 点封面或歌名（1 步） |
| 分组 / 歌单详情 | 同上（播放条不属于列表区，详情态仍在） |
| 车载设置 | 底部常驻条 → 封面 / 歌名 / 「播放页」按钮（1 步） |
| 完整设置（六卡 + 任意子页） | 顶栏右侧「播放页」（1 步） |
| 播放页本身 | 顶栏「收起」或返回键回曲库 |

**为什么设置页要有常驻条而不是只加一个按钮**：设置是车机上最容易被"顺手打开"的页面（改个歌词字号、
看一下版本），而它一盖上来就遮住了底部播放条。常驻条顺带承担了「现在放的是哪首、能不能换一首」的
确认作用 —— 这也是 Google 车机 UI 里 now-playing 一直可见的原因。

### 11.4 实现要点（别踩）

1. **分支在 `SettingsScreen` 入口**：`player.carMode && !fullSettings` 时直接走 `CarSettingsScreen`
   并 `return`，手机端与既有测试一行不改；新增的六个回调（`onOpenPlayer` / `onTogglePlay` /
   `onPrevious` / `onNext` / `onRescan` / `onOpenScanScope`）全部带默认值。
2. **开关整行可点**：`Switch(onCheckedChange = null)` —— 开关自己再接一次点击会出现「点边缘不响应」
   （Compose 只把点击给最内层）。`contentDescription` 仍写标题，读屏与测试都靠它。
3. **步进不夹错边界**：速度 0.75~2.00（步长 0.05）、变调 ±12、歌词字号 0.7~1.6（步长 0.05），
   范围与手机版滑块**同一套**，否则同一项在两处能调出的值会不一样。
4. **「完整设置」要能退回来**：顶栏返回键与系统返回键都先退车载设置页（`fullSettings = false`），
   再按才关设置 —— 否则用户会直接掉回曲库，以为自己误关了什么。
5. **入口不能时有时无**：没有当前曲时常驻条仍然渲染，只把控制键换成一句说明；播放页入口保持稳定。
