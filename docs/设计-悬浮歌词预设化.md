## 二、背景与目标

### 2.1 背景

悬浮歌词自 v1.1.1 完善方案落地后持续增强：v1.1.29 按应用隐藏、v1.1.51 参数四组重排、v1.1.52 拆出独立设置子页并补齐 10 项样式参数（圆角 / 边框 / 行距 / 描边 / 当前行颜色 / 淡出时长 / 标题模式等）。能力已从「4 个 Prefs 键」增长到 **20+ 可调参数**，入口也从 1 处增加到 2 处（设置子页 + 播放设置弹层）。

### 2.2 要解决的问题

| # | 问题 | 用户侧表现 | 代码侧证据 |
|---|---|---|---|
| Q1 | **参数面板化** | 设置子页一屏放不下 20+ 参数，用户面对「工程师面板」，不知道先调什么；调乱后无法一键回到可用状态 | `SettingsOverlayPage.kt`：位置与尺寸 / 字体 / 背景 / 行为四组，颜色项各带任意取色弹层 |
| Q2 | **入口深且分散** | 播放中想开 / 关 / 换样式，要退出播放页进三级设置；两处入口语义还不一致（设置页有完整配置，播放弹层只有开关） | `SheetsPlayback.kt` L306-328「歌词」分组仅「桌面悬浮歌词」开关 + 导出歌词 |
| Q3 | **场景形态单一** | 只有一种「深色圆角底板单条 / 三行」外观；驾驶、驻停、游戏、阅读、桌面听歌对悬浮窗的诉求完全不同 | `LyricOverlayService.kt` 单一 `FrameLayout + TextView` 渲染管线 |
| Q4 | **车载场景弱** | 车机只是「字号大点」；强光、触控板、导航分屏场景没有专属方案 | 车机设置仅一行「桌面悬浮歌词」开关（`06-car.html` 车机设置屏） |

### 2.3 目标与成功指标

| 目标 | 成功指标（口径） | 目标值 |
|---|---|---|
| G1 降低配置门槛 | 新用户从「想开悬浮窗」到「看到一个好看可用的悬浮窗」的操作步数 | ≤3 步（开开关 → 选预设 → 完成） |
| G2 高频操作不离开播放页 | 播放中完成「开关 / 换样式」的比例（在播放设置弹层内完成 ÷ 全部该类操作，本地计数，见 §十二） | ≥80% |
| G3 场景覆盖 | 上线时可选择的外观方案数 | 手机 **4 套** + 车机 **3 套**（D3 拍板后口径） |
| G4 不破坏既有底线 | 既有三原则（锁定时零干扰 / 前台不重复 / 失败必须自证）回归通过率 | 100%（见 §十五） |

> 指标口径说明：G2 的「本地计数」见 §十二——本应用**零网络权限**（既有定位，旧方案 §八已把联网歌词搜索列为不做），因此全部指标只做**本地计数**，用于设置页「最近使用」排序与自检报告，不做任何远程上报（D4 拍板确认）。

### 3.2 现有参数清单（单条形态，共 21 项）

| 组 | 参数（Prefs 键） | 数量 |
|---|---|---|
| 位置与尺寸 | 宽度 / 盒高 / 水平位置 / 垂直位置 / 行数 | 5 |
| 字体 | 正文字号 / 对齐 / 文字颜色 / 当前行颜色 / 上下句亮度 / 行距 / 描边宽度 / 描边颜色 | 8 |
| 背景 | 不透明度 / 颜色 / 圆角 / 边框宽度 / 边框颜色 | 5 |
| 行为与标题 | 显示歌名歌手 / 标题字号 / 标题内容 / 淡出时长 / 暂停表现 | 5 |

**结论：参数多且相互耦合**（如「行数 × 盒高 × 行距」共同决定窗口高度，「描边宽度 × 文字颜色 × 背景不透明度」共同决定可读性）。这正是 Q1 的根源——**问题不是参数不够，而是缺少「一组好参数」的快捷通道**。

### 3.3 现有入口（2 处）

1. 设置 → 悬浮歌词子页（`SettingsOverlayPage.kt`）：完整 21 项 + 授权引导 + 自检；
2. 播放设置弹层 → 「歌词」分组 → 「桌面悬浮歌词」开关（`SheetsPlayback.kt` L311）。

## 四、名词与术语

| 术语 | 定义 |
|---|---|
| 预设（Preset） | 一组**已调好的参数组合**，用户一键套用；本质是现有 Prefs 键的批量快照，**不引入新渲染引擎** |
| 形态 | 悬浮窗的两种结构：**单条形态**（默认，1~3 行字幕条）与**整屏形态**（`lyricOverlayFullHeight`，占满屏幕的歌词面板）。预设系统只作用于单条形态 |
| 全局参数 | 不随预设切换的参数：行数、点击穿透、锁屏行为、按应用隐藏名单、自检 |
| 车机专属预设 | 标记 `carOnly` 的预设（3 套），仅车载模式可见 / 可套用；按车机场景设计（D3） |
| 歌词菜单 | 播放设置弹层的「歌词」分组升级版（本期入口整合的落点，D2 拍板） |
| 速选面板 | 歌词菜单内展开的预设 chips + 当前预设差异参数卡 |
| 驾驶中简化 | ~~车速 > 10km/h 时强制降为「导航窄条」~~ · **状态：已否决 / 不做（2026-10-25）**；历史设计见 §7.2 / FR-08 |

## 五、方案对比与选型

| 维度 | 方案 A：预设快照（推荐） | 方案 B：皮肤包资源化 | 方案 C：参数精简 |
|---|---|---|---|
| 思路 | 内置 7 套参数组合，切换 = 批量写现有 Prefs；用户可基于任一套微调，微调后可「恢复预设原值」 | 把每套做成独立布局资源 / 渲染管线分支 | 删减参数到 ~8 项 |
| 实现成本 | **低**（纯 Prefs 读写 + 一个新 Compose 页面，无渲染改动） | 高（多套布局、多套夹取逻辑，测试面翻倍） | 中 |
| 用户体验 | 好（一键可用、可微调、可还原） | 好 | 差（删掉的参数有人要用） |
| 风险 | 低（不动窗口生命周期） | 高（21 项参数 × 多形态组合爆炸） | 中（破坏既有用户配置习惯） |
| 与既有底线 | 兼容（全形态只展示、锁定态穿透不松，见 §9.1） | 需逐套重新论证穿透原则 | — |

**推荐方案 A**，理由：① 与现状架构同构（参数本就在 Prefs），改动集中在设置层；② 保留全部 21 项参数的完整能力（不减配）；③ 效果图第 8 章即按 A 设计，用户已确认。方案 B 的「液态渐变 / 旋转唱片」等视觉，在 A 中通过**底板颜色 + 圆角 + 边框 + 封面取色**参数组合实现，不新增渲染管线（封面取色能力已存在于 `AppVisual.coverBrush`）。

**演进路径**：本期（A）→ 后续若本地计数证明某形态高频，再考虑把该形态独立成渲染分支（B 的单点化），触发条件见 §十四。

## 六、信息架构与入口整合

### 6.1 入口整合（Q2 · D2 拍板）

```
播放设置弹层（歌词态 / 封面态均可开）
└── 「歌词」分组 = 歌词菜单（升级）
    ├── 桌面悬浮歌词        [开关] · 副标题常驻「当前：<预设名>」
    ├── 悬浮窗样式 ›        缩进行 · 显示当前预设名 → 打开速选面板
    └── 导出歌词为 LRC      既有
```

- **不新造顶栏菜单**（D2 拍板）：歌词菜单落在**播放设置弹层的「歌词」分组**，与代码现状路径一致、改动最小、封面态也能开。效果图 08 §1 的「顶栏 ⋮」描述在开发首日按本口径修正，本文为口径真源。
- 设置 → 悬浮歌词子页保留完整配置，**顶部新增「当前预设」状态卡**（开关 + 运行态 + 当前歌词预览），与歌词菜单形成「快捷 ↔ 完整」的配对，语义一致。

### 6.2 设置子页改版（Q1）

```
设置 → 悬浮歌词
├── 状态卡：开关 + 运行态（已授权 / 未授权 / 运行中）+ 当前歌词预览
├── 样式预设：2 列预设网格（手机 4 套；车机 3 套仅车机模式显示）+「恢复预设原值」按钮（仅微调后出现）
├── 全局参数：行数 / 点击穿透 / 锁屏行为 / 按应用隐藏名单
└── 高级（折叠）：现有 21 项参数原样保留，入口文案「高级参数（预设已覆盖大部分场景）」
```

## 七、预设规格表

> 每套 = 现有 21 项参数的组合快照。「封面取色」指 `AppVisual.coverBrush(stableKey)`（已存在的能力，非新增渲染）。
> 表中数值为该预设的**默认组合**，用户可改，改后可一键还原。
> **D1 拍板：全部预设只展示，无任何控制按钮**——播放控制由通知栏媒体卡 / 桌面小组件 / 车机方向盘按键承担（竞品调研亦证实车机场景控制靠方向盘按键，见 `docs/竞品调研-车机音乐应用.md`）。

### 7.1 手机预设（4 套）

| 预设 | 定位与适用场景 | 关键参数组合 | 触摸行为 |
|---|---|---|---|
| **P1 极简单行** | 游戏 / 阅读 / 强干扰场景；最低存在感 | 行数 1；盒高 0（自适应）；底板不透明度 72%；圆角全圆角；无边框；不显示上下句 | **穿透**（锁定态零干扰） |
| **P2 毛玻璃双行** | 桌面听歌**默认**；信息量适中 | 行数 2；底板 = 玻璃（`glassBg` + `glassBorder`，API 31+ 真模糊，低版本退高不透明度近似）；圆角 14dp；显示歌名歌手（标题模式：歌名·歌手） | **穿透** |
| **P3 液态渐变 · 唱片** | 想要个性与音乐感；封面好看时 | 底板 = `coverBrush` 渐变（跟随封面取色开）；唱片缩略开；圆角 16dp；靛蓝投影 `windShadow(2)`；显示歌名·歌手 | **穿透** |
| **P4 经典方块** | 喜欢「小卡片」观感；信息全（封面 + 歌名 + 当前行） | 方角 8dp 纸底；左封面 40dp；歌名·歌手 + 当前行；**无播放控制键**（D1） | **穿透** |

### 7.2 车机专属预设（3 套，按车机场景重新设计 · D3 拍板）

设计依据（`docs/竞品调研-车机音乐应用.md` 核实）：
① 车机悬浮窗的核心价值是**导航时看歌词**（「7 分屏」白名单对侧载应用封闭，悬浮歌词是第三方在车机看歌词的主通道）；
② 竞品车机「导航时仍显示桌面歌词」是标配，强光高对比、大按钮是通用规格；
③ 方向盘按键覆盖播放控制 → 悬浮窗无需按钮（与 D1 一致）。

| 预设 | 场景与定位 | 关键参数组合 | 触摸行为 |
|---|---|---|---|
| **C1 导航窄条**（驾驶默认） | **驾驶中 / 导航占用大屏**：贴边、窄、大字、高对比，不挡地图路线与转向箭头 | 行数 1；正文字号车机 24sp 档加粗；深色实底 90% + 高对比描边 1.5dp；高度 ≤64dp；贴顶居中偏右；不显示歌名与上下句 | **穿透**（车机触控板误触率高，更不能吃触摸） |
| **C2 驻停歌词** | **驻停等待**（红灯 / 等人 / 充电）：屏幕空闲，信息量与美观优先 | 行数 3 + 歌名·歌手；玻璃底（强光下车机玻璃底对比度不足时自动加深，见 NFR-6）；行距加大；居中 | **穿透** |
| **C3 纯净浮层** | 车机桌面本身干净 / 大屏已在看播放页歌词时做辅助浮层 | 无底板；纯文字 + 轻投影；单行中小字；低存在感 | **穿透** |

**驾驶中简化规则（历史设计 · 已否决）**：原拟「车速 > 10km/h 强制降为 C1；兜底判据：蓝牙已连且未充电」。**2026-10-25 用户决策：不做 / pass**。实现与验收均不再排期；车机用户可手动选 C1「导航窄条」作为驾驶默认。下文 FR-08 / 验收项 11 仅作历史备查。

**整屏形态**：`lyricOverlayFullHeight` 开关保持独立（不进预设网格）——它是「结构切换」不是「皮肤」，与预设混在一起会造成「选了预设却变了结构」的困惑。整屏形态参数沿用现有宽 / 高 / 位置三滑杆。

## 八、参数分层模型

```
┌────────────────────────────────────────────┐
│ 预设（7 套，一键套用 = 批量写 Prefs）            │
│  位置尺寸 / 底板 / 字体颜色 / 标题             │  ← 预设级（约 16 项）
├────────────────────────────────────────────┤
│ 全局参数（不随预设变）                          │
│  行数策略上限 / 点击穿透 / 锁屏行为 /            │  ← 全局级（5 项）
│  按应用隐藏名单 / 自检（驾驶中简化开关 · 已否决） │
└────────────────────────────────────────────┘
```

| 规则 | 说明 |
|---|---|
| R1 套用即写盘 | 切换预设 = 把该预设的预设级参数一次性写入 Prefs（与手改同一通道），服务每帧读 Prefs，**立即生效无需重启** |
| R2 微调可还原 | 用户改过任一预设级参数后，预设卡出现「已修改」角标 + 「恢复预设原值」按钮（二次确认：恢复会覆盖你的手动修改） |
| R3 全局不被覆盖 | 套用预设**不得**改写全局级参数（尤其「按应用隐藏名单」与「点击穿透」偏好） |
| R4 车机写回全局 | 车机模式套用车机预设时，写的是**全局当前预设 ID**——退出车机后悬浮窗保持同一套（效果图 08 ㉝ 已确认的口径） |
| R5 零迁移 | 全部沿用现有 Prefs 键，**不新增键、不做数据迁移**（重装即重置的本项目既有口径）；「当前预设 ID」仅作为派生展示值，由现有参数反推匹配（匹配不到 = 「自定义」） |

> R5 的「反推匹配」是故意设计：不引入「当前预设」这个新状态源，避免「预设 ID 与实际参数不一致」的双源真相问题。反推失败显示「自定义」，与「恢复预设原值」按钮的出现条件共用同一判定。

## 九、关键设计决策（四项已拍板，§十七）

### 9.1 D1：悬浮窗全形态只展示，无任何控制按钮（用户拍板）

| 冲突项 | 视角 A（旧原则） | 视角 B（效果图初稿） |
|---|---|---|
| 悬浮窗上的播放控制 | 旧方案 §八明确「不做」：锁定态必须 `FLAG_NOT_TOUCHABLE`，加按钮 = 整窗挡桌面操作 | 效果图 08 ㉛/㉝ 的经典方块与车机预设画了播放键 |

**裁决（用户拍板）**：**全形态只展示**。P4 经典方块去掉三键退化为「封面 + 歌名 + 当前行」的展示卡；车机预设同样不含任何按钮。播放控制由三个既有渠道承担：通知栏媒体卡、桌面小组件、车机方向盘按键（竞品调研证实车机场景方向盘按键是标配，控制需求已被覆盖）。

**收益**：「锁定时零干扰」原则**完整保留**——全部 7 套预设锁定态均 `FLAG_NOT_TOUCHABLE`，桌面 / 导航操作零被挡；原风险 RK-1（吃触摸投诉）随之关闭。车机触控板误触率高，此裁决在车机场景收益更大。

### 9.2 D2：歌词菜单落点为播放设置弹层「歌词」分组（用户拍板）

见 §6.1。效果图 08 §1 的顶栏 ⋮ 形态让位于弹层改造（代码路径一致、封面态也可用）。**实施时以本文 §6.1 修正效果图 08 §1 的描述。**

### 9.3 D3：车机预设按车机场景重新设计，只做车机版（用户拍板）

原方案「P5 迷你胶囊 + P3/P4 车机版」作废，改为从车机场景推导 3 套专属预设（C1 导航窄条 / C2 驻停歌词 / C3 纯净浮层，规格见 §7.2），并配套「驾驶中简化」安全规则。手机池保持 4 套（P1~P4）。

### 9.4 D4：指标只做本地计数（用户拍板）

见 §十二。不引入任何网络上报。

## 十一、异常处理清单

| 场景 | 表现 | 处理 |
|---|---|---|
| 授权被系统收回 | 悬浮窗消失 | 既有对账机制：回置开关 + 设置页提示（不因预设改动而改） |
| ROM 禁止挂窗（MIUI 类） | 开了没反应 | 既有三级降级 + 手动路径文案；预设无关 |
| 歌词为空 / 无时间轴 | 回落歌名 | 既有 `OverlayContentResolver` 行为；预设只影响外观 |
| 与其他悬浮窗 App 冲突（导航 / 行车记录仪） | 两个窗重叠 | 既有「按应用隐藏名单」；**本期不做**自动避让（见 §十三 RK-3） |
| 分屏 / 小窗模式 | 位置可能越界 | 既有夹取逻辑；预设 shall not 绕过夹取 |
| 用户在速选面板快速连点多个预设 | 渲染抖动 | 写盘幂等，末次生效；UI 层 300ms 内合并点击（should） |
| 车机车速信号不可用 | 驾驶中简化不触发 | 兜底判据（蓝牙已连接且未充电）；仍不可用则保持完整形态并在自检报告标注 |
| 驾驶中简化与用户所选预设不一致 | 用户困惑「我选的样式没生效」 | 歌词菜单开关副标题在行驶中显示「行驶中 · 导航窄条」；自检报告同口径 |
| 恢复预设原值时服务被杀 | 参数写盘成功但窗未重绘 | 既有自愈（30s 节流）+ 自检「重新拉起」就地动作 |

## 十八、实现备注（v1.1.78 落地记录，2026-10-24）

| # | 与 v2.1 的差异 / 澄清 | 理由 |
|---|---|---|
| N-1 | **出厂默认不是任何一套预设的快照**，参数与出厂值完全一致时显示「默认预设」（FR-01 口径），命中某套快照才显示预设名，其余「自定义」 | 保「老用户升级零变化」：若把 P2 设为出厂值，老用户从没动过的 1 行字幕会突然变 2 行 |
| N-2 | P3「液态渐变·唱片」本期按方案 A 的参数组合实现（深紫底 82% + 淡紫当前行高亮 + 16dp 圆角 + 细边框）；**唱片缩略与封面取色未做**（需新渲染能力，方案 §五本就未承诺） | 不新增渲染管线 |
| N-3 | 「已修改 + 恢复预设原值」（FR-04 / R2）的「上次套用」记在**进程内**（`OverlayPresetTracker`），不落盘；重启后记忆消失，但网格上重新套用即可，不构成缺口 | 坚守 R5 零新键；反推匹配已覆盖「当前是哪套 / 是否自定义」 |
| N-4 | 「全屏高度」结构开关放在预设网格**上方**且不进「高级参数」折叠 | 方案 §7.2：整屏形态是结构切换不是皮肤，混进预设会造成「选了预设却变了结构」 |
| N-5 | 预设快照共 **24 项**（行数 / 宽 / 高 / 位置 / 字体 8 项 / 标题 3 项 / 背景 5 项 / 行为 2 项，对齐现有 Prefs 键）；「全局不碰」落实为：主开关 / 全屏形态 5 项 / 隐藏名单 | §八 参数分层的可执行口径 |
