# 悬浮窗：判定结果缓存 + 刷字快判（A-OV2 / A-OV1）

> 版本锚点：随 **v1.2.46** 出包（代码已合入 main）。对应 `docs/规划-资源性能续开发.md` §4.1。
> 不改播放行为、不改显隐规则本身，只减少「每帧都要做但几乎每次结果都一样」的工作。

## 1. 背景

悬浮窗是**常驻**的：只要开着，显隐判定就跟着播放进度每帧跑一遍（约 2 次/秒）。
v1.2.44 车机诊断包显示：判定 → 重算 27 次 → 实际变化 26 次，
说明**规则本身没错、重算也没有空转**，剩下的开销全在「每帧的准备动作」上：

| 每帧动作 | 原代价 | 本轮处理 |
| --- | --- | --- |
| 读隐藏名单 `prefs.lyricOverlayHiddenApps` | `getStringSet` **每次 new 一个 HashSet**（防调用方篡改） | A-OV2：进程内只读快照 |
| 拼接「画什么」指纹字符串 | 含歌词当前 / 翻译 / 待机 / 上下句全文，几百字符 | A-OV1：先用引用 + 标量快判，命中即不拼 |

## 2. A-OV2 · 隐藏名单判定结果缓存

`Prefs.lyricOverlayHiddenApps` 的读改为**进程内只读快照**：

- 首次读取时取一次 `getStringSet`，包成 `unmodifiableSet` 存字段，之后直接返回同一实例；
- 写入时同步换掉快照（先换快照再写盘），所以「设完立刻读」一致；
- 返回只读视图是刻意的：调用方若就地 `add` 会当场抛 `UnsupportedOperationException`，
  而不是悄悄改掉所有读取方看到的名单却不落盘。

一致性边界：`Prefs` 是进程内按 Application 缓存的单例，名单所有写入路径都走该 setter
（设置页 `OverlaySettings.setLyricOverlayHiddenApps` → `SettingsRepository` → setter），
不存在「别人改了存储、快照没跟上」的窗口。

配套把「判定次数」单独计数（`OverlayMetrics.onVisibilityEval`），诊断包从此能读到
**判定 → 重算 → 变化** 三段数字，而不只有后两段。

## 3. A-OV1 · 刷字快判

`OverlayStateBinder` 原来每帧都拼一份含歌词全文的指纹字符串，只为和上一帧比一次。
现在先做**零分配**的快判：

```
content 对象引用相同
  && appearanceRev 相同
  && 全屏形态相同
  && 行数相同
  && 强调态相同
  ⇒ 一定不用重画
```

成立时连字符串都不拼。`LyricOverlayBus.content` 是 `StateFlow`（同值不重发），
所以「引用相同 ⇒ 逐字段相同」是成立的；引用变了但文案等价的情况（例如只翻了
`playing`）仍回落到原字符串细比，不丢任何一次该刷的帧。

⚠️ 重订阅（`observe()` / `dispose()`）时必须把快判状态一起清空 —— 否则上一轮的
内容引用会让第一帧被误判成「没变」，表现为「重开悬浮窗后首句不出字」。已清。

## 4. 验收

| 项 | 怎么看 | 期望 |
| --- | --- | --- |
| 判定 / 重算 / 变化 | 诊断包 `[悬浮窗]` 开销行 | 判定 ≫ 重算 ≈ 变化 |
| 刷字 / 跳过 | 同上 | 同句重入时跳过递增、刷字不动 |
| 跟词准时 | 主观 | 不变（本项不动 ticker 与渲染内容） |
| 切 avc / 桌面 | 主观 | 显隐仍灵敏（防抖窗口未改） |
| 名单生效 | 设置页勾选后切到该应用 | 立即收起；取消勾选立即恢复 |

单测：`PrefsHiddenAppsTest`（5 项）、`OverlayStateBinderTest`（8 项，新增「同内容重入只记跳过」
与「判定每帧计数」）。

## 5. 不做

- 不改 `OverlayVisibility.show` 的任何规则（全屏 / 调整 / 预览 / 暂停隐藏 / 名单五条例外原样）。
- 不改前台包名 450ms 滞回窗口（A-OV2 只缓存**读取**，不缓存「包名是什么」）。
- 不放慢跟词 ticker。
