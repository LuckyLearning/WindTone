# 版本历史

版本号遵循语义化版本；`versionCode` 每发一版 +1，打上 `vX.Y.Z` 的 tag 后由 GitHub Actions 自动构建签名 APK 并创建 Release。

> ⚠️ 标注了「重建数据库」的版本会清空歌单 / 收藏 / 播放统计 / 歌词偏移（详见[权限与更新](权限与更新.html)）。

| 版本 | 主要内容 |
|---|---|
| **1.1.18** | **新增「双语歌词」显示开关 + 修「重开后当前曲歌词为空」**。<br>• **双语歌词三选一**（用户提出）：设置 → 歌词 → **双语歌词**，可选**中英都显示 / 只显示中文 / 只显示英文**，默认「都显示」= 历史行为，老用户升级后看到的行不变。判定是纯函数（`BilingualLyrics.apply`）：主行已是目标语言 → 只藏译文；副行是目标语言 → **把副行提上来**；两边都不是（日文歌 + 罗马音副行，选了「只中文」）→ 留主行，绝不因为找不到目标语言就整行消失；间奏空行永远原样保留。日文假名 / 韩文谚文**不算**中文也不算英文，避免「日文歌 + 中文翻译」这个最常见的双语场景选错行；混写行（`Yeah 我是`）两种模式都保留原样。<br>• 只影响**显示**：歌词文件、导出的 LRC（译文仍完整写入）都不动。切换**立即生效且不重读文件**——原始歌词常驻内存，切模式只是重新裁一遍，当前歌不闪空白。播放页与悬浮窗读的是同一份过滤结果，不会出现「播放页过滤了、悬浮窗没过滤」的错位。<br>• **修「重新打开软件后当前曲歌词没加载出来」**（用户真机上报，下一曲再切回来才恢复）。恢复链路里歌词只加载一次，那一次读到空就永远停在空态；冷启动瞬间文件系统 / MediaStore 可能还没就绪（车机杀进程狠，尤其明显），隔几秒再读就正常。模拟器复现不了，按**结果**自愈：恢复完成后 2s / 5s / 10s 三次复查，当前曲歌词仍空且不在加载中就重载一次；歌词到了、正在加载、换过歌都立刻收手，自愈只盯着恢复时那一首，日志写明「歌词自愈：重载当前曲歌词」。顺带修掉一个加载竞态：被取消的旧加载请求会把「取消异常」当普通失败吞掉、回写一次空歌词 —— 现在用序号挡住，晚到的旧请求不许覆盖新歌的歌词。<br>• 补测 11 条：双语裁剪的三种模式、间奏空行、无副行原样、两边都不匹配、混写行、空译文、空歌词、文字语言判定（汉字 / 拉丁 / 假名 / 谚文 / 混写 / 纯符号）、非法档位回落；另加设置页入口回归 1 条。单测 269 → **281 项**。<br>• 本版**不重建数据库**（schema 仍为 v5）。 |
| **1.1.17** | **新增「曲库格式与容量」统计页**（用户提出：统计当前音乐库各种格式的数量与占用）。<br>• 入口在 **设置 → 音乐库 → 格式与容量**，入口行右侧直接给出摘要「N 首 · X GB」，不进页面也能看到总量。<br>• 页面三段：**汇总**（歌曲总数 / 合计占用 / 总时长 / 平均每首 / 格式种类）、**按占用排序的格式分布**（每种格式的首数、占用、占比条、平均码率与平均每首大小）、**无损 / 有损拆分**（各占多少首、多少空间）。<br>• 格式识别顺序是**文件名后缀 → 绝对路径后缀 → MIME**，不能颠倒：MediaStore 的 MIME 常年写 `audio/mpeg`（连 `.m4a` 都可能这么报），先信 MIME 会把一半 FLAC 统计成 MP3。同格式别名归一（`wave→wav`、`oga→ogg`、`m4b/mp4→m4a`、`mpga→mp3`），避免 `WAV / WAVE` 拆成两行各占一半。<br>• **`m4a` 计入「有损」**：它既可能是 ALAC 也可能是有损 AAC，光看扩展名判不出来；页面底部写明了这条口径，不假装精确。<br>• 脏数据按"只计首数、不计占用"处理并单独提示条数：读不到文件大小的歌（老系统 / 外部存储未挂载时 `length()` 为 0）不会让合计凭空变小而无从解释。<br>• 统计**只读内存里的曲库**（当前可见的歌），不查库、不碰文件系统、不落表：曲库本身已是"当前有哪些歌"的唯一真相，再查一遍只会得到第二份可能对不上的数字。聚合是纯函数 `buildLibraryStats`。<br>• 补测 16 条：格式识别（大小写 / 别名 / 路径兜底 / MIME 兜底 / 文件名压过错误 MIME / 认不出）、聚合与排序（占用降序、并列时首数再扩展名）、零大小与未知时长、无损拆分（含 m4a 归有损）、空库、容量文本；另加 1 条设置页入口回归。单测 253 → **269 项**。<br>• 本版**不重建数据库**（schema 仍为 v5）。 |
| **1.1.16** | **新增「打开应用继续上次播放」开关**（用户提出）。<br>• 语义：打开应用时**从上次的进度接着播**。默认开启 —— 车机场景里那一下播放键恰恰最不顺手（要看路），而「队列恢复了但停在暂停态」对用户来说等于没恢复。<br>• 关掉它回到老行为：队列、当前曲、进度照旧恢复，只停在暂停态等用户点，其余一切不变。<br>• 恢复链路本来就齐（`player_state` 每 5 秒落一次进度、`queue_songs` 存整个队列、循环 / 随机模式一起恢复），本版补的只是「恢复完要不要顺手起播」；顺带在起播前重套一次速度 / 变调 / 跳过静音 —— 这是全应用唯一一条**没人按播放键**的起播路径，参数没跟上就没有任何界面动作能纠正它。<br>• 修一处旧实现的死角：队列已存在时（播放服务还活着、只退过界面）原代码直接 return，「开关打开却没续播」最容易出在这里。现在这条分支也会按开关把暂停态接着播下去。<br>• 顺带修掉断点续播本身的**时序隐患**（模拟器上实测撞到）：恢复动作会在「曲库还没推给引擎」时被静默跳过，而当次就把「已恢复」标志置真，于是这次启动**永久**失去恢复机会 —— 表现是底部迷你条和当前曲都不出现，不报错、不崩溃，看着就像"没恢复"。现在改成条件不具备就等下一次调用（缓存装载后 / 扫描完成后各一次），并把实际走的路径写进日志（`断点续播：恢复队列 7 首，第 6 首，位置 65488ms`）。<br>• 补测：判定抽成纯函数 `shouldAutoResume`（开关开 / 关 × 队列空 / 已在播共 4 条），设置页新增 1 条（开关在界面上、↺ 写回出厂默认），默认值一致性断言 1 条；单测 248 → **253 项**。<br>• 模拟器（1920×1080）端到端双向验证：开关开 → 强停后重开自动从 65488ms 接着播（media_session 为 PLAYING）；开关关 → 同样的场景恢复到暂停态（PAUSED，位置不变），迷你条与「回到当前播放」都在。<br>• 本版**不重建数据库**（schema 仍为 v5）。 |
| **1.1.15** | **悬浮歌词窗增强：顶部歌名歌手 + 行数 1–5 可调**（用户提出）。<br>• 新增开关**「显示歌名与歌手」**：开启后悬浮窗最上面多两行小字（歌名 / 歌手），下面是原来的歌词。默认关闭，老用户升级后看到的仍是纯歌词字幕；歌手拿不到时（`<unknown>`）只显示歌名一行，不写「未知歌手」。<br>• 这两行有自己的**字号三档**（小 / 中 / 大，默认小、约为歌词的六成），与歌词字号完全独立 —— 歌词调大不会把标题顶出去。颜色跟随歌词文字色、压低到 ~70% 不透明度，换色时两处一起走。<br>• **歌词行数由 1 / 3 两档扩成 1–5 连续可调**：当前行居中高亮，上下带上下文（3 行 = 上下各 1，5 行 = 上下各 2，偶数行时下方多一行）。解析层一次取上下各 2 句，组装层按用户选的行数裁；双语副行**不占**行数额度，仍紧跟当前行。<br>• 实现上标题是**独立的 TextView**（与歌词同装在一个纵向 LinearLayout 里），而不是拼进歌词串：这样两处字号、行距、显隐互不干扰。标题显隐会改变窗口高度，代码在布局完成后重新夹一次位置，避免窗口变高后出屏。<br>• 补测：组装器 6 条（2 / 3 / 4 / 5 行、上下文不足时收缩、副行不占额度）+ 解析器 2 条（上下文列表顺序、跳过间奏空行），单测 242 → **248 项**。<br>• 模拟器实测（1920×1080 / 240dpi）：开标题 + 5 行时正确显示「歌名 / 歌手 / 上 2 行 / 当前行 / 下 2 行」，末句时自动收缩为 3 行；release（R8）包结构一致。<br>• 本版**不重建数据库**（schema 仍为 v5）。 |
| **1.1.14** | **修车机上「设置点不到」+ 停用双栏**（同一位比亚迪宋 L DM-i 2026 款车主续报，紧接 1.1.13 的黑屏修复）。<br>• 现象：左侧导航最下面的「设置」被车机自带的固定按钮栏（Home / 应用 / 空调那一条）压住，**看得到、点不到**；同时明确不要双栏布局。<br>• 根因：那条 Dock 是**车机自己画的浮层，不属于系统导航栏** —— `WindowInsets.navigationBars` 实测为 0，`navigationBarsPadding()` 拿到 0dp，布局于是一路铺到屏幕最底，正好被浮层盖住。这类问题在手机上永远复现不了。<br>• 修：根布局统一上抬到安全线 `padding(bottom = bottomSafe)`，`bottomSafe` 取「系统导航栏 insets」与「车机 Dock 保底 56dp」的较大值（仅 `widthDp ≥ 840` 时启用保底）。`Surface` 背景仍铺满全屏，Dock 后面不会露出色差；顺手修好手机三键导航盖住迷你播放条的老问题。<br>• **双栏整体下线**：车载两栏（`CarHomeScreen`）与平板双栏一起停用，所有尺寸统一「单栏 + 抽屉导航」，车载模式保留启动直进播放页 / 歌词 5 秒收起 / 开机自启三项行为。`CarHomeScreen.kt` 保留在仓库里但不再被调用，文件头写明了原因与恢复前提。<br>• 补测：布局契约测试改写 —— 删掉「钉住分隔线写法」那条，换成 `noTwoPaneLayout`（禁止 `MainScreen` 再出现 `VerticalDivider(` / `CarHomeScreen(`）与 `mainScreenReservesCarDockHeight`（钉住 Dock 保底常量与 `padding(bottom = bottomSafe)`）。模拟器按 1920×1080 / 240dpi / 深色实测：单栏正常、抽屉里「设置」完整落在安全区内、车载模式启动直进播放页也不再是两栏。单测 241 → **242 项**。<br>• 本版**不重建数据库**（schema 仍为 v5）。 |
| **1.1.13** | **修「车机 / 平板打开全黑」**（比亚迪宋 L DM-i 2026 款真机上报，DiLink 5.0 / Android 12 / 1920×1080）。<br>• 现象：装上点开，屏幕**停在纯黑一动不动** —— 没有崩溃对话框、进程也活着；同一个包在手机上完全正常。<br>• 根因：宽屏双栏（≥840dp）里那条分隔线写成了 `Modifier.fillMaxSize().width(1.dp)`。`fillMaxSize()` = `fillMaxWidth() + fillMaxHeight()`，它在 `Row` 里把**整行宽度**吃满，两个 `weight(...)` 子节点（左侧列表 / 右侧播放页）只能分到 **0 宽** —— 整屏只剩主题背景色，深色模式下就是纯黑。这条分支只在 `widthDp ≥ 840` 时才走，手机竖屏（约 411dp）永远测不到，所以从 1.1.3 双栏上线起一直没暴露。<br>• 修：分隔线改为 `fillMaxHeight().width(1.dp)`。已按车机参数（1920×1080 / density 240 / 深色 / 横屏）在模拟器上复现黑屏，改完同一条件下左列表 + 右播放页正常显示。<br>• 补测：新增**布局契约测试**（源码扫描：禁止 `fillMaxSize()` 后接 `width/height`；并钉住分隔线的写法），做了**反向验证** —— 改回旧写法两条用例立刻变红。单测 229 → **241 项**。<br>• **修「三个快捷方式点下去只是把应用打开」**（用户真机上报，v1.1.12 修好「未安装应用」之后立刻暴露）。<br>• 现象：长按图标点**播放全部 / 随机播放 / 我的收藏**，应用起来了，但一个动作都没执行 —— 没起播、也没进到收藏页。根因是**两个互不相干的 bug 叠在一起**。<br>• **①「就绪」判据在第一帧就判成成立**：旧判据是 `曲库非空 或 扫描范围未选 或 不在扫描`，冷启动第一帧三条同时"看着像"成立（曲库还是空、扫描还没开始、范围是上次存的值），于是待执行的动作被当场消费掉，`playQueue(空队列)` 又被内部的空判断**静默丢弃** —— 表现就是「什么都没发生」。现在只认两个明确的装载完成标志（曲库首批装载给出结论 / 虚拟歌单曲目已算好），并抽成纯函数统一判断，三个入口共用一套判据。<br>• **②「我的收藏」按 id 去歌单列表里找**：`playlists` 里**只有自建歌单**，收藏 / 最近 / 最常是界面现拼的虚拟视图 → 永远找不到 → 只切了个视图就结束，于是停在歌单列表页。新增统一的虚拟歌单构造函数，列表页与快捷方式共用同一份来源。<br>• 补测：单测 215 → **229 项**（就绪判据 + 虚拟歌单 + 崩溃取证各一组），并做了**反向验证** —— 把判据改回旧写法，用例立刻变红；布局契约测试再并入一版，最终 **241 项**。模拟器端到端三条全过（播放全部从第一首起播、随机播放后播放器状态确为随机 + 列表循环、打开收藏停在收藏页），应用已在前台时再点也照常起播。<br>• 新增**启动取证**（这次黑屏排查的副产物，留在包里）：应用在 `Application` 与 `Activity` 的每个启动阶段落一行记录（到「首帧」为止），上一轮崩过或没画出画面时，启动先摆一张**纯原生 View** 的诊断页（设备 / 系统 / 屏幕 / insets / 窗口与显示 / 上一轮阶段表 / 崩溃栈），可一键复制或拍照。刻意不用 Compose —— 界面的问题不能靠界面自己报。<br>• 本版**不重建数据库**（schema 仍为 v5）。 |
