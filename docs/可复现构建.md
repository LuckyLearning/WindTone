# 可复现构建（E3）

> 日期：2026-10-31（Asia/Shanghai）  
> 状态：**文档 + 哈希脚本落地**；**不改构建图、不打 tag、不发版**  
> 目标：钉死并公开记录 JDK / AGP / Gradle / SDK 组件版本；任何人能按同一套步骤出包，并对 APK/AAB 算 SHA-256 与本机或 CI 对照。

## 1. 一句话结论

本仓已经用 **Version Catalog + Gradle Wrapper + 固定 CI 镜像** 把「用哪套工具链」钉死了。  
E3 要补的是：**把钉死的版本写进一页真源**，并给出**本机算哈希**的固定命令——**不追求**两台机器打出字节级完全相同的 APK（Android/R8 常见会因时间戳、路径元数据等有差异），而是让「版本是否一致、产物是否被篡改」可核对。

## 2. 当前钉死的版本（真源）

| 项 | 当前值 | 真源文件 |
| --- | --- | --- |
| **Gradle** | **8.9** | `gradle/wrapper/gradle-wrapper.properties` → `distributionUrl=…/gradle-8.9-bin.zip` |
| **AGP** | **8.7.2** | `gradle/libs.versions.toml` → `[versions] agp` |
| **Kotlin** | **2.0.21** | 同上 → `kotlin` |
| **KSP** | **2.0.21-1.0.27** | 同上 → `ksp`（前半段必须与 Kotlin 一致） |
| **编译目标 JVM** | **17** | `app/build.gradle.kts` → `compileOptions` / `jvmTarget = "17"` |
| **CI 运行 JDK** | **Temurin 17** | `.github/workflows/android-ci.yml` / `android-release.yml` → `setup-java` |
| **本地跑 Gradle 的 JDK** | 建议 **OpenJDK 21**（或任意能跑 Gradle 8.9 的 JDK ≥17） | 本机 `JAVA_HOME`；**不要**用带 graal 路径的发行版跑单测（见 `docs/AI开发指南.md` §7 / §8） |
| **compileSdk / targetSdk** | **35** | `app/build.gradle.kts` |
| **minSdk** | **24** | 同上 |
| **CI / Release Runner** | **ubuntu-24.04**（刻意不写 `ubuntu-latest`） | 两个 Android workflow |
| **CI SDK 组件** | `platform-tools` + `platforms;android-35` + `build-tools;35.0.0` | workflow 里 `sdkmanager --install` |
| **产品版本号** | `appVersionName` / `appVersionCode` | **只在** `app/build.gradle.kts` 顶部（不进 Catalog） |

配套关系（升版本时一起动才安全）：

```
AGP 8.7.x  ↔  Gradle 8.9  ↔  编译目标 Java 17
Kotlin 2.0.21  ↔  KSP 2.0.21-*
```

依赖坐标一律走 `gradle/libs.versions.toml`；脚本里只写 `libs.*`，禁止字面版本号（产品自身 versionName/Code 除外）。细则见 `docs/AI开发指南.md` §2。

## 3. 本地与 CI 对齐检查清单

发版前或怀疑「我这机能编、CI 不能 / 哈希对不上」时，按序核：

1. **Wrapper**：`gradle/wrapper/gradle-wrapper.properties` 的 `distributionUrl` 是否仍是 `gradle-8.9-bin.zip`。  
2. **Catalog**：`agp` / `kotlin` / `ksp` 是否与上表一致；`./gradlew help` 能配置成功。  
3. **编译目标**：`sourceCompatibility` / `targetCompatibility` / `jvmTarget` 仍为 **17**（即使本机 `JAVA_HOME` 是 21）。  
4. **CI**：workflow 仍是 `java-version: '17'` + `temurin` + `ubuntu-24.04` + 同上 SDK 三件套。  
5. **签名**：Release 本地与 CI 同一套 `windtone.jks`（CI 用 Secrets 还原）；证书指纹期望见 AI 指南 §8 / `scripts/verify_apk.py` 的 GOLDEN。  
6. **不要**在 `gradle.properties` 里长期写死本机绝对路径的 `org.gradle.java.home`（会让别人克隆后直接炸）；需要对齐时用环境变量 `JAVA_HOME`，或在**本机未入库**的 `~/.gradle/gradle.properties` 里写。

本仓 `gradle.properties` 当前只钉 JVM 参数与并行/缓存开关，**没有** `org.gradle.java.home`——这是刻意的。

## 4. 如何对本机构建产物算 SHA-256

### 4.1 推荐：仓库脚本

```bash
# Git Bash / WSL / Linux / macOS
bash scripts/hash-apk.sh
# 或指定文件
bash scripts/hash-apk.sh app/build/outputs/apk/release/*.apk
```

```powershell
# Windows PowerShell
.\scripts\hash-apk.ps1
.\scripts\hash-apk.ps1 app\build\outputs\apk\release\WindTone-vX.Y.Z.apk
```

无参数时会扫描这些常见路径（存在才列）：

- `app/build/outputs/apk/**/*.apk`
- `app/build/outputs/bundle/**/*.aab`
- `release/**/*.apk`（本地历史包目录，已 gitignore）

输出一行一个：`SHA256  字节数  路径`。

### 4.2 手算（无脚本时）

```bash
# Linux / macOS / Git Bash
sha256sum path/to/WindTone-vX.Y.Z.apk

# macOS 也可
shasum -a 256 path/to/WindTone-vX.Y.Z.apk
```

```powershell
Get-FileHash -Algorithm SHA256 path\to\WindTone-vX.Y.Z.apk
```

### 4.3 与 CI 对照

Release workflow（`android-release.yml`）在打出 `dist/*.apk` 后会对每个文件跑 `sha256sum`，写入 **GitHub Actions Step Summary** 表格（文件名 / 大小 / SHA-256）。

对照步骤：

1. 本机用同一提交、同一签名配置打 Release（或下载 Actions artifact / Release 资产）。  
2. `bash scripts/hash-apk.sh <本机或下载的 apk>`。  
3. 与 Step Summary（或 Release 说明里若附带的哈希）逐文件比对。  
4. **证书**是否为 windtone：用 `scripts/verify_apk.py` 或 `apksigner verify --print-certs`（期望 SHA-256 见 AI 指南）。

应用内更新清单也会带资产 `sha256` 字段（见 AI 指南更新章节）——那是**分发完整性**校验，与「可复现构建」互补。

## 5. 常见坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 两台机器 APK 哈希不同，但都能装 | R8 / zip 时间戳 / 构建路径元数据等导致**非比特级**复现 | 先核版本表与签名证书；哈希不同≠坏包。要比特级需另上 reproducible-builds 专项（本 E3 **不做**） |
| 本机 JDK 21、CI JDK 17，担心不一致 | 编译**目标**已钉 17；运行 Gradle 的 JDK 可以更高 | 保持 `jvmTarget=17`；CI 继续 Temurin 17；本机避开 GraalVM 跑单测 |
| 写了 `org.gradle.java.home=C:\Users\...` 进仓库 | 别人克隆必挂 | 只留在用户级 gradle.properties 或临时 export |
| Wrapper / AGP 只升一边 | 配置期或 AGP 兼容性失败 | 按 §2 配套表一起升，并先跑 `./gradlew help` |
| `./gradlew` 退出码 126（CI） | Windows 丢可执行位 | `git update-index --chmod=+x gradlew scripts/*.sh` |
| sdkmanager 退出码 1 | `setup-android` 默认装已下架的 `tools` | workflow 必须 `packages: 'platform-tools'` |
| Debug 与 Release 哈希无从比 | 签名与 minify 不同 | 只在同 buildType / 同 ABI 分包之间比 |
| 只改了 docs 却想对 CI 产物 | Android CI 已 paths-ignore `docs/**` | 改文档不会出新 APK；对哈希请用代码提交触发的跑次 |
