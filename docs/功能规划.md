# 本地音乐播放器 · 功能扩展规划

> 基线版本：v1.0.0（3785 行 Kotlin / 25 个源文件 / 纯本地无网络权限）
> 规划日期：2026-10-13

---

## 一、现状盘点

### 已经做到的能力

| 域 | 能力 | 关键文件 |
|---|---|---|
| 音乐库 | 三来源合并去重（系统媒体库 / SAF 文件夹 / 深度扫描）、搜索、6 种排序 | `MusicRepository.kt`、`MediaStoreScanner.kt`、`LocalScanners.kt` |
| 歌词 | 同目录 LRC/TXT（多命名规则 + 编码嗅探）、内嵌 SYLT/USLT/TXXX、FLAC Vorbis、MP4 ©lyr | `lyrics/` 全部 5 个文件 |
| 播放 | Media3 MediaSessionService 后台播放、通知栏/锁屏控制、循环/随机、下一首播放 | `playback/` 全部 2 个文件 |
| 界面 | 库列表 + 展开播放页 + 迷你条 + 歌词居中滚动（点击跳转 / 偏移 / 字号） | `ui/` 全部 7 个文件 |

### 架构层面的 5 个缺口（已逐条核实）

**1. 零持久化存储 —— 最根本的一条**
`Prefs.kt` 是唯一的持久层，全部是 SharedPreferences，共 10 个 key，
**没有数据库**。后果：扫描结果不落盘，每次冷启动都要全量重扫（MediaStore + 遍历文件夹 + 深度扫描）。
音乐库上千首时，冷启动会明显卡白屏。且"歌单""播放次数""最近播放"这类数据无处安放。

**2. 断点续播实际是断的**（实锤 bug）
```
Prefs.lastSongUri      ← 只被写，从未被读
Prefs.lastPositionMs   ← 只被写，从未被读
MusicViewModel.resumeQueueIfNeeded()  ← 第 440 行定义，全工程无调用点
```
用户杀掉 App 再打开，播放位置全部丢失。这是"看起来做了但其实没接通"的典型。

**3. 没有"播放列表"概念**
`Prefs` 里没有歌单字段，UI 里没有队列视图。
`playNext(song)` 只能一次塞一首，且用户**看不到队列里有什么、也没法移除/拖拽排序**。
一个音乐播放器没有队列管理，是很突出的功能空洞。

**4. 只有"平铺列表"一种视图**
没有专辑 / 歌手 / 文件夹维度的归组浏览。`Song` 模型里 `albumId`、`trackNo` 字段已经预留了，
但 UI 层完全没有消费。库里 2000 首歌时，平铺列表基本不可用。

**5. 歌词偏移是全局的**
`Prefs.lyricOffsetMs` 是单个全局值。给 A 歌调好偏移后，切到 B 歌会沿用这个偏移，
导致不同来源歌词互相污染。需要改成**逐曲记忆**。

## 二、规划总览

分四批推进，按「补漏 → 核心体验 → 进阶 → 大工程」递进。
每一项都标注了**改动量**（S=改几个文件，L=新增模块级代码）和**是否破坏"纯本地"定位**。

```
批次 1  补漏打底        ── 让现有功能真正可用（无新概念，纯修复+接通）
批次 2  核心体验        ── 让它像个"正经播放器"（歌单/多维视图/音效/定时）
批次 3  进阶增强        ── 差异化能力（逐字歌词/标签编辑/拼音搜索/手势）
批次 4  大工程          ── 需要重构或引三方（数据库/FFmpeg/车载/网络歌词）
```

---

## 三、批次 1 · 补漏打底

> 目标：不引入新概念，把已经写了但没接通的东西接通，把明显的坑填掉。
> 这一批做完，App 的"完成度"会有质的变化。

| # | 功能 | 技术要点 | 改动 | 破坏纯本地 |
|---|---|---|---|---|
| 1.1 | **断点续播接通** | `MainActivity` 启动时调 `vm.resumeQueueIfNeeded()`；扫描完成后按 `lastSongUri` 定位歌曲、`seekTo(lastPositionMs)` 但不自动播放 | J | 否 |
| 1.2 | **播放队列界面** | PlayerScreen 加"队列"抽屉：复用 `MediaController` 的 `getMediaItemAt/moveMediaItem/removeMediaItem`；支持拖拽排序、单条移除、点击跳转 | M | 否 |
| 1.3 | **歌词逐曲偏移记忆** | `Prefs` 增加 `lyricOffset_<stableKey>` 前缀存储；切换歌曲时按 key 读取，无记录回落 0 | S | 否 |
| 1.4 | **空状态与骨架屏** | 首次扫描 / 无权限 / 无结果 / 无歌词 四种空状态视觉；列表加载骨架 | S | 否 |
| 1.5 | **播放失败自动跳下一首** | `Player.Listener.onPlayerError` 里现有实现只提示，改为提示后 `seekToNextMediaItem()`，避免损坏文件卡死队列 | S | 否 |
| 1.6 | **进度条拖拽预览时间** | 目前拖拽中不显示目标时间，加气泡提示 | S | 否 |

**为什么排第一**：1.1 是 bug，1.2 是最大功能空洞，1.3 是用户能直接感知的体验断层。
三项加起来的收益远大于任意一个高级功能。

## 四、批次 2 · 核心体验

> 目标：补齐"正经播放器"的必备件。这一批需要引入 Room 数据库。

| # | 功能 | 技术要点 | 改动 | 破坏纯本地 |
|---|---|---|---|---|
| 2.1 | **歌单系统** | 新建 `data/db/`（Room）：`SongEntity` / `PlaylistEntity` / `PlaylistSongCrossRef`；支持收藏、自建歌单、增删排序、歌单封面（取首曲封面） | XL | 否 |
| 2.2 | **最近播放 / 最常播放** | Room 记录 `playCount` + `lastPlayedAt`，播放时自增；首页加"最近播放"横滑区 | M | 否 |
| 2.3 | **多维视图切换** | 顶部加「歌曲 / 专辑 / 歌手 / 文件夹」四段切换；专辑页取 `albumId` 分组、歌手页取 `artist` 分组、文件夹页取 `folderPath` 分组；进入分组后是曲目列表 | L | 否 |
| 2.4 | **扫描结果缓存** | Room 存歌曲索引 + 文件 `lastModified`/`size`，增量扫描：只重解析变化过的文件，冷启动秒开 | L | 否 |
| 2.5 | **均衡器与音效** | `android.media.audiofx.Equalizer` + `BassBoost` + `Virtualizer`，挂到 ExoPlayer 的 `audioSessionId`；预设 + 自定义 5/10 段 | L | 否 |
| 2.6 | **睡眠定时** | 倒计时 / 播完当前曲 / 播完当前专辑 三种模式；到点淡出暂停（用 `VolumeScaler` 渐弱而非硬切） | M | 否 |
| 2.7 | **主题色跟随封面** | 从当前封面取主色（`Palette` 或自实现中位切分），驱动 Material3 配色；`Theme.kt` 已用 Material3，改造点集中 | M | 否 |
| 2.8 | **桌面小部件** | `AppWidgetProvider` + Glance（或 RemoteViews），显示封面/歌名/播放控制 | L | 否 |
| 2.9 | **快捷设置磁贴** | `TileService`，下拉快捷面板一键播放/暂停 | S | 否 |

**依赖关系**：2.1 必须先于 2.2；2.4 与 2.1 共用 Room，建议一并搭。
**2.3 是这一批里性价比最高的**——`Song` 模型的 `albumId`/`trackNo` 字段早就预留了，等于半成品等接线。

## 五、批次 3 · 进阶增强

> 目标：做别人没有的。这几项是"能拿得出手"的差异化能力。

| # | 功能 | 技术要点 | 改动 | 破坏纯本地 |
|---|---|---|---|---|
| 3.1 | **逐字歌词** | 解析 KRC（酷狗，加密头 + zlib）/ QRC（QQ音乐，DES+zlib）/ YRC（网易云）；`LyricLine` 增加 `words: List<Pair<Long,String>>`；歌词面逐字染色高亮 | XL | 否 |
| 3.2 | **双语歌词对齐** | 识别翻译行（同时间戳多行 / `[lang]` 标签），主行 + 副行双排显示；`Lyrics` 增加 `translated: List<LyricLine>` | M | 否 |
| 3.3 | **标签编辑器** | 读写回音频文件元数据：`MediaMetadataRetriever` 只能读，写需自实现（MP3 ID3v2 写帧、FLAC PADDING 块复用、MP4 ilst 重建）；封面替换 | XL | 否 |
| 3.4 | **拼音搜索** | 汉字转拼音首字母（自实现常用字表或引 `TinyPinyin`），支持"zf"匹配"周杰伦" | M | 否 |
| 3.5 | **字母索引导航** | 列表右侧 A-Z 快速跳转条，按首字拼音归位 | M | 否 |
| 3.6 | **手势操作** | 封面区：左右滑切歌、双击播放暂停、上下滑调音量；`pointerInput` + `detectDragGestures` | M | 否 |
| 3.7 | **变速变调** | Media3 的 `PlaybackParameters` 变速（0.5x–2.0x）；变调用 `SonicAudioProcessor` | M | 否 |
| 3.8 | **M3U 导入导出** | 解析/生成 m3u/m3u8；导入即建歌单，导出用于备份 | M | 否 |
| 3.9 | **歌词导出为 LRC** | 把内嵌歌词导出成 `.lrc` 存到 SAF 目录 | S | 否 |
| 3.10 | **通知栏样式自定义** | 复用 `PlaybackService` 里已设的 `DefaultMediaNotificationProvider`，加深色/紧凑布局 | M | 否 |

**3.1 逐字歌词**是本批技术含量最高的，也是同类开源播放器（如 APlayer、Salt Player）的核心卖点之一。
**3.3 标签编辑器**的风险最高：直接写用户文件，必须做"先备份再写"和失败回滚。

## 六、批次 4 · 大工程与取舍

| # | 功能 | 技术要点 | 改动 | 破坏纯本地 |
|---|---|---|---|---|
| 4.1 | **FFmpeg 解码扩展** | 引入 `media3-decoder-ffmpeg`（NDK 编译或预编译 AAR），补齐 WMA/APE/DSF/TAK 等；包体积 +10~20MB | XL | 否 |
| 4.2 | **Android Auto / 车载** | 基于现有 MediaSessionService 接入 `MediaBrowserServiceCompat` 兼容层，加车机清单声明 | L | 否 |
| 4.3 | **锁屏歌词** | 通过 `MediaMetadata` 的 `SYNOPSIS` 或通知副标题滚动下发当前行 | M | 否 |
| 4.4 | **网络歌词搜索** | 对接网易云/QQ音乐歌词接口，按 歌名+歌手+时长 模糊匹配 | L | **是**，需联网 |
| 4.5 | **跨设备同步** | 歌单/收藏上云 | XL | **是**，需后端 |

### 关于"纯本地"定位的取舍

当前 App **不申请任何网络权限**，这是一个干净的卖点（隐私友好、无广告位、可离线）。
4.4 / 4.5 会直接打破它。建议的处理方式：

- **推荐**：保持主包纯本地，网络歌词做成**独立的可选扩展**（单独 APK 或首次使用时才申请网络权限 + 明示）。
- 若坚持纯本地，用 **3.8 M3U 导入导出** + 手动放歌词文件替代云同步，也能覆盖大部分需求。

## 七、建议执行顺序

```
① 批次 1 全做           ← 收益最高、风险最低，纯修复
     ↓
② 2.3 多维视图 + 2.1/2.2/2.4 歌单与数据库   ← 一次性把 Room 基建打好，后续功能都受益
     ↓
③ 2.5 均衡器 / 2.6 睡眠定时 / 2.7 主题取色   ← 感知强的"配置类"功能
     ↓
④ 3.1 逐字歌词 / 3.2 双语对齐              ← 差异化卖点
     ↓
⑤ 3.3 标签编辑 / 3.4 拼音搜索 / 3.6 手势    ← 打磨
     ↓
⑥ 4.1 FFmpeg / 4.2 车载                    ← 按需
```

**如果只想做一件事**：做 **1.2 播放队列界面**。
它是当前功能完整度上最刺眼的空洞，改动集中（主要动 `PlayerScreen.kt`），
且能立刻让 App 从"能播"变成"能管"。

**如果只能做三件事**：`1.2 队列` + `2.3 多维视图` + `1.1 断点续播`——
这三项补齐后，这个播放器在功能面上就不输主流本地播放器了。

## 八、工程侧配套（不属于功能，但建议同步）

| 项 | 说明 |
|---|---|
| ProGuard/R8 | 当前 `isMinifyEnabled = false`，Release 包 9.6MB。开启后可压到 ~6MB，但需先补 keep 规则（Media3/Room/反射处） |
| 崩溃日志 | 无网络前提下，落地到本地文件，供用户导出 |
| 单元测试 | `LrcParser` / `EmbeddedTags` / `TextCodec` 是纯逻辑，最好测，且当前零测试 |
| 大库性能 | 2000+ 首时的滚动帧率，建议用 `LazyColumn` 的 `key` + 封面异步解码（已有 `LruCache` 但需确认不在主线程解码） |
| 多语言 | 当前 `resourceConfigurations += listOf("zh", "en")`，但 `strings.xml` 只有中文，英文缺 strings 文件 |
