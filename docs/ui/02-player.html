二、播放页

PlayerScreen.kt · PlayerPanes.kt · PlayerScreenParts.kt · LyricsPane.kt —— 三页（歌曲信息 / 图片 + 当前一句 / 歌词）/ 音量浮层 / 暂无歌词 / 纯文本 / 沉浸态（手机 + 车机）
三页横滑（v1.2.55）：播放页中部是三张横排的页 —— 第 1 页 歌曲信息 → 第 2 页 图片 + 当前一句 → 第 3 页 歌词。 左右滑翻页；在第 3 页继续左滑 = 下一首，在第 1 页继续右滑 = 上一首，切歌后回到第 2 页。 翻页阈值取 min(屏宽 18%, 96dp)（比切歌时代的 12% 更钝：误翻会打断正在读的那一句；宽屏按比例要划 300dp，故加上限）， 或者甩得够快（900px/s 且至少划动 24px）也算； 位移与速度冲突时以位移为准（甩出去又拉回来，本意就是不动）。首尾页越界时跟手乘 0.32 阻力、夹在屏宽 30% 内 —— 拖不动多少，但手指能感到「这里到头了」。
纵向不再切歌：歌词页的 LazyColumn 本身就是纵向滚动，旧实现靠「滚到边界才认上下滑」绕开冲突， 实际用起来分不清「在滚歌词还是在切歌」；现在整根纵轴留给滚动，手势与内容一一对应。
手势只挂中部，不挂整页：底部进度条本身就是横向拖动，挂整页必然抢手势。三页都用 Modifier.offset （影响布局位置）平移出屏 —— 用 graphicsLayer 只改绘制，屏幕外的页仍占着原来的命中区域，会把手势抢走。 判据与参数集中在 PlayerSwipe.kt（纯函数，有单测）。
