# UI 效果图（设计基准 / Design Source of Truth）

> `docs/ui/` 目录是听风 WindTone 全部 UI 的唯一视觉真源。
> **任何 UI 改动，先改这里，确认视觉后再改 Compose 代码。**

## 工作流（硬约定）

```
① 打开 docs/ui/index.html（总览：7 章 + 每章屏数 + 全屏索引）
        ↓
② 进入对应分章（01-main … 07-spec），改该章的 HTML
        ↓
③ 浏览器预览确认视觉（默认跟随系统配色，可手动切深/浅）
        ↓
④ 按同一屏下方标注的「Compose 位置」改 ui/*.kt
        ↓
⑤ gradlew assembleRelease 出包真机核对
```

不经过 ①~④ 直接改 Compose 的 UI 变更视为违规改动，需要回补效果图。

硬约定：

- **分章文件里不写内联样式、不写内联脚本** —— 样式进 `ui.css`，行为进 `ui.js`，图标进 `ui-sprite.js`。
- 每屏一个 `<figure class="fig">`；屏数徽标、章节徽标、总览索引**全部由脚本现算**，不手写任何数字。
- 分章之间没有跨页 `<a href="#...">`：链接一律写 `文件名.html#屏id`。
- 双击任一 HTML 都能直接打开（`file://` 下样式 / 图标 / 交互正常；只有总览页的「全屏索引」需要 HTTP，退化为卡片导航）。

## 页面自带的导航能力

- **总览页徽标**：总屏数（HTTP 下脚本扫各章求和）。
- **章节卡片**：每章一张卡，右上角是该章屏数，点进去即该章。
- **每章页头**：7 章切换胶囊（当前章高亮）+ 本页屏数徽标 + 主题按钮。
- **全部屏索引**（总览页 `<details>` 折叠）：脚本扫各章生成，按章列出每一屏，链接直跳 `文件#屏id`。
- **跳转高亮**：从索引点进某一屏，该屏描边高亮，并用 `scroll-margin` 避免被顶栏挡住。
- **页脚翻页**：上一章 / 全部屏 / 下一章。
- **返回顶部**：右下角浮动按钮，滚动超过 600px 出现。
- **打印**：`@media print` 下自动隐藏顶栏导航与索引，方便导 PDF 评审。
- **旧链接兜底**：`index.html#scr-xxx` 这类分章前的锚点，在 HTTP 下会自动重定向到所在分章（`file://` 下不生效）。

## 主题（深 / 浅）

页面**默认跟随系统配色**（`prefers-color-scheme`），与 App 行为一致。右上角按钮可手动切换：

- 点一下 → 切到另一套配色，并记住选择（`localStorage`）
- 手动选过后按钮显示为「🌙 深色主题」/「☀️ 浅色主题」；未选过时后面带「（跟随系统）」，系统主题变化实时跟随
- **双击**按钮 → 清除手动选择，回到跟随系统

主题定位脚本内联在每个页面 `<head>` 最前面（避免首帧闪错色），这是唯一允许的内联脚本。

## 改配色 / 设计令牌

所有颜色集中在 **`ui.css` 顶部**的 `:root` 与 `[data-theme="dark"|"light"]` CSS 变量里。
改配色先改令牌并预览，确认后再同步到 `app/src/main/java/com/luckylearning/windtone/ui/theme/Theme.kt`。

## 新增 / 修改一屏

1. 先到 `index.html` 确认这一屏归哪一章，进对应分章文件；
2. 复制一个相邻的 `<figure class="fig">` 作为起点，改 `id="scr-xxx"`、标题和 `<em>` 里的 Compose 位置说明；
3. 手机壳结构固定为 `statusbar → app(内容) [→ dim → sheet/dialog/menu]`；车机壳为 `carbar → cargrid(carnav + carmain) [→ 底部播放条]`；
4. 复用既有 class（`song-row` / `group-row` / `sheet` / `dialog` / `chip-lsrc` 等），**不要写一次性内联样式**（布局微调除外）；确需新样式一律加进 `ui.css`；
5. **编号规范**：新屏顺延取下一个圈码；**同一屏的另一种状态用字母后缀**（如 ⑫ 的沉浸态 = ⑫D），不占用新号——避免撞号（曾发生过，现已改为 ㉚B / ㉚C）；
6. **屏数徽标 / 章节屏数 / 总览索引都不用手改**（脚本自动生成）；新增**章节**才需要新建文件并在总览页加卡片；
7. 若引入了新颜色/圆角/字号，先加设计令牌，再同步第七节规范表。

## 行组件规范（防画错，与代码一致）

| 组件 | 出处 | 左侧图标 | 右侧元素 |
|---|---|---|---|
| `CategoryRow` | 设置主页（SettingsScreen.kt，v1.1.3） | 有（语义图标，40dp 容器） | 摘要 + 右箭头（二级分类入口专用） |
| `ActionRow` | 设置子页（SettingsScreen.kt） | 无 | 可有「当前值摘要」；箭头只给「点开会进入另一个界面」的行 |
| `OptionRow` | 底部弹层（Sheets.kt） | 有（语义图标） | 无箭头，仅选中态 ✓ |

**chevron 规则**（v1.1.3 收口）：只有设置主页的 `CategoryRow` 与子页里「点开进入另一个界面」的 `ActionRow` 能带右箭头；`OptionRow` 与其余位置仍然不画。

## 图标

全部图标是 SVG `<symbol>`（`#i-xxx`），**集中在 `ui-sprite.js`**，对应 `ui/AppIcons.kt` 的图标集。新增图标时：在 `ui-sprite.js` 的 `SPRITE` 里加 `<symbol>`，并同步在 `AppIcons.kt` 里加同语义图标。

⚠️ 两个坑：① `ui-sprite.js` 用模板字符串承载图标池，**里面不能出现 HTML 注释与反引号**（会截断字符串，整页图标静默消失）；② 弧线路径的 flag 与相邻数字之间**必须留空格**（连写 `0 00` 会让浏览器以外的解析器少读参数）。

## 已知与代码的刻意差异

- 效果图里的封面是渐变占位（真实 App 用专辑封面或取色占位）。
- 效果图数据为示例数据（500 首、1,284 首云端曲目等），版本号示例随当前版本更新。
- 桌面小组件背景固定浅色（App 内不随主题），效果图中如实呈现。

## 自查清单（改完效果图后跑一遍）

1. 圈码无重复：列出全部 `<div class="cap">`，确认编号唯一；
2. 结构平衡：**逐个文件**核对 `<figure>` / `</figure>`、`<div>` / `</div>`、`<section>` / `</section>` 数量相等；
3. 屏数合计：9 章效果图 `figure.fig` 之和 = 总览页徽标数（当前 **94**；手机 78 / 车机 16）；
4. 图标无缺失：每个 `<use href="#i-xxx">` 都在 `ui-sprite.js` 里有对应 `<symbol>`；
5. 链接可解析：`<a href="文件.html#屏id">` 的目标文件与锚点都存在，分章之间没有裸 `#锚点`；
6. 脚本语法：`node --check ui.js` 与 `node --check ui-sprite.js`；
7. 浏览器控制台无报错（可用 `--headless --dump-dom` 确认 `<symbol>` 已注入）。
