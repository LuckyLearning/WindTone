# 竞品调研 · 车机音乐应用

> 调研于 2026-10-18（在线资料：官方说明、更新公告、车主实拍反馈；车上应用市场需真机核实）。
> 对标对象：**汽水音乐车机版**（`com.luna.music.car`）与 **QQ音乐车机版** —— 在 DiLink 上适配得最好、被车主提及最多的两个参考竞品。
> 结论先行：**听风与竞品的差距不在版式，而在「默认音乐」语音注册与语音点歌能力**。原先「分屏入口是白名单制、侧载无门」的判断已于 **2026-11-14 订正**（见 §六：车机读的是清单里的一条元数据，Cardash 就是活证据），听风已按同一机制接入。

## 一、两款竞品的交互逻辑

### 汽水音乐车机版（30~40MB，字节）

- **布局**：横屏「**左封面 + 播放控制 / 右滚动歌词**」，上下滑动切歌；大按钮 + 高对比度；左上角一键切换场景模式（驾车 / 通勤 / 助眠 / 夜间放松等 10+ 智能播放模式）。
- **语音**：V1.1.27 起**深度适配小迪** ——「播放抖音热歌」「播放周杰伦」「下一首」「音量调大」「收藏这首歌」全链路执行。前提：车机设置里把它设为**默认音乐播放器**。
- **其他**：方向盘按键（播放 / 暂停 / 上一首 / 下一首 / 音量）；左导航右歌词的**分屏**；抖音扫码登录、手机歌单同步；车载音效引擎；无广告。

### QQ音乐车机版

- **布局**：单栏首页**六大版块** —— 「当前播放」最大卡片（点进播放详情页：歌词 + 进度 + 收藏 / 暂停 / 删除 / 切歌）+ 最近播放 + 本地音乐 + 为你推荐 + 个性电台 + 我的音乐；左上角设置（扫码登录）、右上角搜索（文字 + 语音输入）。
- **语音**：与小迪同类集成（歌曲搜索、播放控制、切换歌单）；方向盘 + 中控旋钮盲操；**导航时仍显示桌面歌词**。
- **其他**：日夜模式；手机资产同步。

## 三、小迪语音的接管机制（关键）

「你好小迪播放音乐」的完整链路：

1. 用户唤醒小迪并下达音乐指令；
2. 车机读**车辆设置 → 智能提醒 → 智能语音 → 「默认音乐」**里选定的应用；
3. 该应用此前**注册过语音服务**（声明「支持歌曲搜索与播放控制」）；
4. 语音指令送达应用执行：起播 / 切歌 / 音量 / 收藏 / 点歌。

要点：

- **「默认音乐」选择器只列注册过语音服务的应用**。未注册的第三方（含听风）连列表都进不去 —— 这是听风「语音完全叫不动」的根因。
- 方向盘按键走的是 MediaSession 标准通道，**与语音注册是两套机制**，所以听风「方向盘能用、语音不能用」。
- 新 OTA 动向（汉L/唐L）：**「7 分屏」（三七分）选择器的默认列表只有 10 个预置 / 合作应用** —— 2026-10-19 用户真机截图证实，可选列表是：电话 / ETC / 文件管理器 / 哨兵模式 / 相册 / 地图 / 音乐 / 天神之眼 / 爱奇艺 / 优酷视频。**但这不等于「包名白名单」**：2026-11-14 从 Cardash 的清单里挖到车机实际读的是 `BYD_SUPPORT_SPLIT_ACTIVITY` 元数据（见 §六），侧载应用自己声明就能进。**仪表歌词目前只对系统音乐（酷我 / 酷狗 / 网易云 / QQ音乐）开放**，第三方暂无通道。
- **屏幕不可旋转**（用户 2026-10-19 确认）：车机屏固定横屏，`SCREEN_ORIENTATION_USER_LANDSCAPE` 在全屏下是空操作；它只在多窗口里有害（letterbox），而多窗口入口就是上面那个白名单选择器 —— 两件事叠加，**方向锁在本机无需改动**。
- **「伪装成白名单应用」评估（2026-10-19，用户提问后）**：不可行。社区先例（音乐助手的「酷狗包名版」装成 `com.kugou.android.auto`）成立的前提是**酷狗是用户可自装应用、车里没预装**；而 7 分屏白名单里 10 个（电话 / ETC / 文件管理器 / 哨兵模式 / 相册 / 地图 / 音乐 / 天神之眼 / 爱奇艺 / 优酷视频）**全是预装应用**（系统分区或合作预装），同包名应用装不上去、系统应用也卸不掉，**没有 root 就无法顶替**。剩下唯一未验证的路径是「选择器按 intent-filter / 权限查 PackageManager 而非硬编码包名」——需要 adb 连车机逆向选择器组件才能定论。⚠️ 即便技术上走得通，**冒充「电话 / ETC / 哨兵模式」这类系统应用有行车安全风险**（用户以为点在打电话，实际落到我们 App），不做；冒充「音乐」同品类预期一致，但同样撞包名。**分屏的用户价值已被悬浮歌词覆盖大半**（导航时看歌词 = 分屏的典型用途，且不依赖白名单）。

### 调研结论：三条通道，只有一条适合听风（2026-10-18 深挖）

**① 官方合作通道（现状：进不去）**
比亚迪 2026-09 发布的「迪迪虾」智能体把语音生态升级为**开放平台（A2A / MCP 标准协议）**，但**音乐智能体的首发合作方是 QQ音乐 / 酷我 / 酷狗 / 网易云四家**；汽水音乐的小迪适配同样是字节与比亚迪的合作版本。这是**商务合作制**，独立开发者短期无法进入。

**② 社区 hack 通道（现状：不适合产品化）**
第三方「比亚迪音乐助手」（远方的小熊猫）用两条 ADB 指令让任意应用"被小迪叫到"：

```
adb shell cmd notification allow_listener <包名>/<NotificationListenerService>
adb shell pm grant <包名> android.permission.READ_LOGS
```

原理是**伪装成通知监听器 + 读取系统日志**，从小迪的识别结果里截获音乐指令再代为执行。代价：要用户执行 ADB、要 READ_LOGS（signature 级权限）、**0920 及更新系统已注册不到默认音乐列表**、切歌可能被系统媒体中心抢占。**不作为听风的功能路线**，仅作为机制佐证记录在此。

**③ 自研平替通道（结论：这才是听风该做的）**
「说歌名点歌」不必依赖小迪 —— 竞品的搜索框本身就支持**输入法语音听写**（QQ音乐车机版右上角搜索即文字+语音双输入）。听风车机版加一个麦克风入口 → 系统听写转文字 → 直接搜本地曲库起播，**零合作门槛、零 hack、当天就能上线**。这是当前唯一现实的「语音点歌」。

## 四、优先级修正（2026-10-18 调研后）

原判「默认音乐注册 = P0」**降级**：官方合作制进不去、hack 路线不产品化 → 转为**观望项**（关注比亚迪生态开放平台后续是否对个人开发者开放音乐技能注册）。新的 P0 替换为：

| **已声明，待真机确认** | 默认音乐注册 / 语音点歌直控 | **2026-10-27 补齐三条系统识别依据**（`CATEGORY_APP_MUSIC` / `ACTION_VIEW` + 音频类型 / `MEDIA_BUTTON`）并声明 `MEDIA_PLAY_FROM_SEARCH`（按查询词搜曲库起播）。能否出现在车机「默认音乐」列表里取决于 DiLink 读哪条依据，**要真机看**（清单 P0-N15，诊断包新增「默认音乐候选资格」段可自检）；把应用设为默认音乐这一步只能用户在系统设置里操作 |

## 六、订正（2026-11-14）：7 分屏不是包名白名单

### 证据

对比 `source1/` 下四份反编译清单（Cardash 2.33 / 2.30 / 1.57、迪迪宋 1.30）：

| 应用 | 侧载 | `BYD_SUPPORT_SPLIT_ACTIVITY` | `resizeableActivity` |
|---|---|---|---|
| Cardash 智屏车联 | 是 | **有**（`@integer/byd_support_split_activity`） | `true`（application + Activity） |
| 迪迪宋工具箱 1.30 | 是 | 无 | `false` |

Cardash 是纯侧载的第三方应用，却照常出现在车机多窗口入口里 —— 说明选择器**不是**按包名枚举，而是读清单里的这条元数据。2026-10-19 那次截图只看到了默认列表的 10 个预置应用，误把「列表里没有第三方」当成了「第三方进不去」。

### 机制（Cardash 的写法，逐字照抄）

```xml
<!-- AndroidManifest.xml，<application> 下 -->
<meta-data android:name="BYD_SUPPORT_SPLIT_ACTIVITY"
           android:value="@integer/byd_support_split_activity"/>
<meta-data android:name="android.allow_multiple_resumed_activities"
           android:value="true"/>
```

```xml
<!-- res/values/integers.xml        --> <integer name="byd_support_split_activity">0</integer>
<!-- res/values-v32/integers.xml    --> <integer name="byd_support_split_activity">1</integer>
```

分档是关键：分屏是 Android 12L（API 32）才有的能力，老系统读到 0 就不会把应用列进去。
另外 `application` 与目标 Activity 都显式写 `android:resizeableActivity="true"`，并把
`density` 加进 `configChanges`（车机可能按窗口下发不同密度，不自己处理就会重建界面）。

### 听风侧的两件事

1. **声明**：清单 + 两个 `integers.xml`，契约测试 `SplitScreenContractTest` 守住（写错名字 / 丢了 `@integer/` 前缀 / 漏了分档都会静默失效，编译期不报错）。
2. **降级**：3:7 分屏后窗口可能只剩三成宽（DiLink 5 上约 384dp）。车机版式的常驻侧栏是 208dp，扣掉只剩 176dp，不可用。所以 `FormFactor.resolve` 增加一条：**设备是车机但窗口 < 600dp 时按手机版式渲染**（抽屉导航 + 单列播放页）；用户显式拨了「车载模式」时仍优先 CAR。

### 尚未验证

- 选择器里是否真的出现「听风」（真机验证清单 §11 W-17）；这依赖车机侧实现，我们只能保证清单声明正确。
- 分屏后是否还有额外的窗口行为（例如强制自由窗口比例、`onMultiWindowModeChanged` 的时序），需要上车看。
- 仪表歌词仍是另一条通道，与分屏无关，继续保持观望。
