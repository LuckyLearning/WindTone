## 二、逐项说明

### 1. 智能歌单

复用既有虚拟歌单机制（`VirtualPlaylist` 负数主键），新增两个：

- **从未播放**（`-5`）：`playCount == 0`，最多 100 首；
- **很久没听**（`-6`）：`lastPlayedAt` 落在「30 天前 ~ 更早」，按**最久未听**排序，最多 100 首。

口径刻意不重叠：从未播放的歌不参与「很久没听」（它压根没播过，归前一组）。
判定是纯函数（`neverPlayedSongs` / `dormantSongs`），入参 `nowMs` 由调用方给，单测可固定时间。
UI 侧与「最近播放 / 最常播放 / 我的收藏」完全同构（列表行、封面四宫格、点即播），没有第二套列表。

### 2. 音频焦点丢失策略

设置 → 播放 →「音频焦点丢失时」，三档：

| 档 | 抢焦点时 | 拿回来时 |
|---|---|---|
| 标准 | 交给 Media3 内建（暂停 / 自动恢复） | 内建 |
| 降音量 | 瞬时丢失与 can-duck 都降到 20% 音量 | 恢复到原音量 |
| 继续播放 | 不理 | 确保没被压着 |

实现要点：一旦选「降音量 / 继续播放」，就把播放器 `handleAudioFocus` 关掉、自己发
`AudioFocusRequest`（API 26+，低版本走旧重载），避免两套焦点逻辑互相打；降音量走
`TrackVolume` 的独立衰减因子，不改用户音量值，恢复时不会把用户拖过的音量顶回去。
车机导航播报是这条策略的主要收益场景。

### 3. 耳机适配档案

均衡器预设新增两条**听感曲线**（不是 AutoEQ 型号库）：

- **耳机·入耳**：低频抬升 + 3.5k 附近轻微压（压掉「轰头 / 齿音」）；
- **耳机·开放式**：低频收敛 + 高频抬（补偿开放式的低频泄漏与高频滚降）。

同时各配一条同名音效方案（`SoundSchemes`），这样「按设备自动挂档」可以直接选它们。
内置型号级 AutoEQ 曲线库没有做 —— 那是几百条数据的维护工程，与「离线、不联网」的取舍不划算。

### 4. 音效按输出设备自动挂档

设置 → 播放 →「音效按输出设备自动挂档」：

- 设备键：蓝牙按**设备名**（`bt:WH-1000XM5`，读不到名字退化为 `bt`）、有线 `wired`、USB `usb`、扬声器 `speaker`；
- 绑定表是纯文本 `设备键=方案id` 每行一条，坏行忽略；
- 接入时若该设备有绑定 → 先拍快照再套方案；拔掉 → 用快照还原挂档前的样子；
- 同一台设备的重复回调（系统常连发）是 no-op，不会反复拍快照；
- **车载模式不参与**：车载音效档案（`carSchemeId` + `soundStash`）走另一套快照，互不覆盖。

### 5. 多播放队列（队列快照）

播放页 →「播放队列」弹层顶部新增快照区：**保存当前队列**（默认名 `队列 MM-dd HH:mm`）、点一条恢复、右侧删除。

- 只存**歌曲主键**，不存 URI —— 恢复时按主键回表，DAO 自带「已移出 / 文件丢失」过滤，失效歌自动剔除；
- 一并存当前序与进度，恢复后接着听；
- 上限 20 条、同名覆盖并置顶（快照是「常用几套听法」，不是第二个收藏夹）；
- 序列化 `名称\t序号\t进度\t保存时间\tid,id,id`，纯文本、JVM 可断言。

### 6. 车载蓝牙歌词（AVRCP，实验）

设置 → 实验室 →「车载蓝牙歌词」：把**当前歌词行**写进 `MediaMetadata.title`（歌名让位到 `artist`），
车机中控 / 仪表这类只读 AVRCP 元数据的地方也能看到歌词 —— 这条通道**不经过 DiLink 白名单**，
所以对 BYD 车机是「绕过限制」的通用方案。

- 与锁屏歌词共用同一个 `LockScreenLyricPublisher`，一次 `replaceMediaItem` 同时写 `description`（锁屏）与 `title/artist`（蓝牙）；
- 歌词行超 40 字截断；关掉开关后立刻把原标题 / 原艺人还原；
- 默认关：它会改变蓝牙端「歌名」的显示位置，属于会让人意外的行为，因此只放在实验室；
- 真机风险：部分车机对元数据更新有节流，可能出现「歌词比声音慢半句」——见真机验证清单。

### 9. 假无损识别

歌曲 `⋮` →「音频信息」新增一行「无损成色」。判据只有一条但可靠：**有损编码必然砍掉高频**。

- 只对无损容器（flac / wav / aiff / ape / dsf / dff / alac，或 MIME 命中 flac/alac/pcm/raw/wav）判定，其余显示「不适用」；
- 取中段 3 秒解码成单声道 PCM，2048 点 Hann 窗 + radix-2 FFT，从高频往下找首个过阈频点 = 频谱截止；
- 截止 < 16.5 kHz → 「疑似有损转码」；否则「看起来是真无损」；
- 采样率 < 32 kHz（22.05k / 24k 素材）不判，直接「判不了」—— 否则全线误报；
- 只在用户主动打开信息页时才解码，默认不做后台扫描。

### 10. 文件夹黑名单

设置 → 音乐库 →「扫描黑名单」：每行一条规则，可以是**目录名**（`录音`）或**路径片段**（`DCIM/Camera`）。

- 匹配是**路径段级**：目录名全等，或规则在完整路径里作为完整路径段出现；`录音` 不会误伤 `录音棚精选`；
- 文件夹扫描命中即剪枝（整棵不递归，省掉读标签的 I/O）；
- 媒体库（MediaStore）是摊平的行，按文件路径判定，命中直接跳过；
- 改规则后自动重扫（扫描范围已选时才触发）；不改变「软删 / 主动移出」的既有语义。

### 12. 交叉淡化：核对后不做

结论记档：现有「淡入淡出」是**曲边界淡变**（前一首淡出结束后下一首淡入），不是曲间**重叠**。
真正的 crossfade 需要两个播放实例交错或自定义 `AudioProcessor` 接管混音，会牵动
媒体会话、进度上报、通知/锁屏、断点续播、车机投屏等一整条链 —— 引擎层大改，与
「车机 GPU 弱、常驻渲染要省」的红线反向。本版不做，保留现状；如后续要做，应单独立项。

### 13. Material You 动态取色

设置 → 外观 →「Material You 动态取色」（Android 12+）：

- 取色优先级：**封面取色（seed）> Material You > 手写色板**；
- 低于 Android 12 时开关置灰/无效果，不崩；
- 明暗仍只由 `MainActivity` 一处分派（沿用既有约定），本项只换色源。
