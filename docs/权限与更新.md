# 权限与更新

## 权限说明

| 权限 | 用途 | 何时申请 |
|---|---|---|
| `READ_MEDIA_AUDIO`（33+）/ `READ_EXTERNAL_STORAGE`（≤32） | 读取系统媒体库 | **仅在你选择「扫描全盘」时** |
| `MANAGE_EXTERNAL_STORAGE`（可选） | 全盘模式下的深度扫描，读取同目录 `.lrc` | 在 `⋮` 菜单中手动开启 |
| `POST_NOTIFICATIONS`（33+） | 播放控制通知 | 首次播放时 |
| `FOREGROUND_SERVICE(_MEDIA_PLAYBACK)` / `WAKE_LOCK` | 后台播放 | 安装即声明 |
| `INTERNET` / `ACCESS_NETWORK_STATE` | **仅**用于访问 `api.github.com` 检查更新、从 GitHub 下载新版本 APK | 安装即声明，实际只在检查/下载时使用 |
| `REQUEST_INSTALL_PACKAGES` | 下载完成后调起系统安装器 | 首次应用内安装时由系统弹窗确认 |
| `SYSTEM_ALERT_WINDOW`（「显示悬浮窗」） | 桌面悬浮歌词 | 开启悬浮歌词时引导到系统设置授权 |
| **无障碍服务**（`BIND_ACCESSIBILITY_SERVICE`，v1.1.29 新增） | 感知前台应用切换，实现「按应用隐藏悬浮窗」与「前台应用记录」 | **完全可选**：只在用户配置名单或打开记录时才需要，在系统设置里手动开启；服务只监听窗口切换事件、**不读取屏幕内容** |
| **使用情况访问**（`PACKAGE_USAGE_STATS`，v1.1.29 新增，可选） | 同上的备用检测通道 | 完全可选；两个通道任一可用即可，**都不可用时按「不隐藏」放行**，悬浮窗不会因此消失 |

> **关于网络权限**：这是本应用唯一的联网能力，只为「应用内更新」服务，
> 只请求 `api.github.com` 与 GitHub 的 Release 下载地址，不采集、不上传任何信息。
> 在「设置 → 更新」中关闭「启动时自动检查更新」后，应用不会发起任何网络请求。
> 歌单、收藏、播放统计、歌词偏移、崩溃日志全部只保存在本机。

### 关于 `.lrc` 歌词的获取条件（重要）

系统媒体库（MediaStore）本身不索引 `.lrc` 文件，Android 10 之后 App 也无法直接访问音频同目录的普通文件。因此要使用**独立歌词文件**，在「扫描范围」里二选一：

- **方式 A（推荐，不需要任何权限）**：扫描范围选「指定目录」→「选择音乐目录…」，用系统文件选择器授权音乐目录。授权后可读取该目录树下的音频与 `.lrc`。
- **方式 B（扫描全盘 + 深度扫描）**：扫描范围选「扫描全盘」，再在 `⋮` 菜单里授予「所有文件访问权限」（深度扫描），之后重新扫描。

内嵌歌词不受此限制，任何时候都能读取。

## 应用内更新是怎么实现的

应用内置了版本检测，不用再手动下载：

- **设置 → 更新 → 检查更新**，或库页右上角 `⋮` →「检查更新」；
- 发现新版本时会显示版本号、安装包大小和更新说明，点「下载并安装」即可；
- 下载完成后调起系统安装器，确认后完成升级；
- 「启动时自动检查更新」默认开启，每 24 小时最多检查一次，**检查失败不打扰**；关闭后应用完全不联网。

> 更新源是**公共分发仓库** `LuckyLearning/Release`（源码仓库是私有的，安装包单独放在这个公开仓库里，按「软件 / 版本」分目录，只保留最近 5 个版本）。无需登录、无需 Token。第一次从应用内安装时，系统会要求你允许「听风」安装应用。

### 流程

```
App 启动 / 用户点「检查更新」
        │
        ├─ 拉取 latest.json（检查与下载共用「设置 → 更新 → 下载线路」）
        │     · 默认「自动」：国内优先并行竞速
        │         fastly/gcore.jsdelivr → gh-proxy.com → ghproxy.net → 官方 raw 兜底
        │     · 静态清单，**不消耗 GitHub API 配额**
        │     · 一次拿全：版本号 / 版本码 / 发布时间 / 更新说明 / 每包大小与 SHA-256
        │
        ├─ 与 BuildConfig.VERSION_NAME 做语义化比较（3.10.0 > 3.9.2）
        │
        ├─ 有新版本 → 弹窗展示版本号 / 大小 / 更新说明
        │
        ├─ 按本机 ABI 选包：arm64-v8a → 其它 ABI → universal
        │     下载到 cacheDir/updates/（写 .part；失败换线可 Range 续传；
        │     慢线路可在弹窗里点「切换线路」；装包前 SHA-256 校验）
        │
        └─ 校验：zip 头 + 字节数 + **SHA-256** → FileProvider 交给系统安装器 → 用户确认 → 覆盖安装
```

关键实现都在 `data/UpdateChecker.kt`，几个刻意的设计：

- **不引入 OkHttp / Gson**，用 `HttpURLConnection` + Android 内置 `org.json`，避免为了一个更新功能撑大包体；
- **国内默认可达优先**：AUTO 先走 jsDelivr Fastly/Gcore 等 CDN，官方 GitHub raw 作最后兜底；
  检查更新多线并行竞速，避免「先卡官方超时再换线」；
- **失败静默**：自动检查失败（离线 / 限流 / 仓库没发版）只打日志，不弹任何提示；
- **手动检查的失败会给明确原因**，例如「网络不可用」「连接超时」「仓库还没有发布版本」；
- 跨线路保留 `.part` 并用 HTTP Range 续传；校验失败才会丢掉半截文件；
- 下载完成后做三层校验：文件头（zip/APK）、字节数、**SHA-256**（清单里给了摘要就逐字节比，
  镜像只该转发字节，内容被替换必须拒绝安装）；
- **只保留最近 5 个版本**：公共仓库由发布流水线维护，每次发布新版本会删掉第 6 个及更旧的目录。

> 维护者视角的发版流程（打 tag 即出包、4 个 ABI 产物、并发到公共仓库、脚本自动裁剪到 5 个版本）见 [发版规则](版本号发版规则.html)。

## 已知限制

- WMA / APE / DSF 等格式需要额外解码器，当前版本会跳过（列表统计里会提示数量）。
  补齐需引入 `media3-decoder-ffmpeg`，代价是包体积 +10~20 MB。
- 系统媒体库来源的歌曲，默认无法匹配同目录 `.lrc`（Android 存储沙箱限制），
  需要「导入文件夹」或「深度扫描」。
- 「编辑歌曲信息」只做**应用内显示覆盖**（`song_overrides` 表），不写回音频文件。
- 应用内更新依赖 GitHub 可达性；网络受限时可在设置页点「打开发布页面」手动下载。
- 桌面悬浮歌词只支持在 Android 8.0+ 上运行，且需要系统「显示悬浮窗」授权；部分厂商 ROM
  （HyperOS / MIUI / DiLink）还需额外把应用加入白名单或放行「后台弹出界面」，细节见设置页的「悬浮歌词自检」。
- 音频信息里的「位深」取决于容器是否声明该字段，WAV / FLAC 一般有，MP3 一般为空。
- 车机媒体面板（Android Auto / 车机自带面板）可以浏览**歌单层级**——根目录下是
  「我的收藏 / 最近播放 / 最常播放」＋每个自建歌单，点进去是该歌单的曲目，可整单播放。
  浏览树目前**只做这一层**：不做专辑 / 歌手 / 文件夹三种视图，也不支持车机侧搜索
  （车机面板的屏幕与操作方式决定了它只适合「选一个歌单，从头放」）。
