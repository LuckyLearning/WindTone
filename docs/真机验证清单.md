# 真机验证清单

> 生成于 2026-10-16，对应 **v1.1.28**（schema v5）。
> **同日追加**：逐字歌词功能已整体移除并随 **v1.1.8** 发布，本清单里与逐字染色相关的项已同步删掉，并补了一项 P0-24 复核移除结果。
> **v1.1.9 追加**：车机媒体面板由"只能播放控制"升级为**歌单层级可浏览**（服务改 `MediaLibraryService`），新增 P1-6 / P1-7 / P1-8 三项待真机确认。
> **v1.1.28 追加**：车机播放页三项修复（控制键居中 / 沉浸态贴底 / 上一曲图标乱码），新增 **P0-42**。

> 用途：模拟器（AVD）能回答的问题**已经在模拟器上回答过了**，这份清单只保留**只有真机才能回答**的部分。
> 建议直接测你手上的装机包（`WindTone-v1.1.28-<架构>.apk`），不要用 debug 包——性能项对构建类型极其敏感。

## 0. 怎么用

- **P0** = 阻塞发布，必须过；**P1** = 强烈建议，影响口碑；**P2** = 有空再说。
- 每项只写「怎么做 → 期望是什么」。**不通过时**先别急着描述，用附录的命令抓一份日志，那比回忆准确得多。
- 记录方式：直接在表格最后一列的 `☐` 里打勾，或在旁边补一句结论。
- 建议用**一台主力机 + 一台车机（或车机模拟环境）**走一遍；ROM 差异本身就是这轮要测的东西之一。

## 2. P0 · 阻塞发布

### 2.1 桌面悬浮歌词（历史上出过两次问题，重点中的重点）

背景：这个功能被用户报回**两次**，两次根因都不是渲染 bug，而是设备相关
（一次是坐标系混用，一次是「屏宽 − 窗口宽 = 0」的几何必然）。
所以要**在尽量不同的屏宽/DPI 下各试一遍**。

| # | 验证项 | 怎么做 | 期望结果 | 结果 |
|---|---|---|---|---|
| P0-1 | 授权链路 | 设置 → 歌词 → 打开「桌面悬浮歌词」（未授权时应自动跳授权页） | 能落到**本应用**的悬浮窗授权页；部分 HyperOS/MIUI 会打开空列表——此时界面应给出手动路径提示，不静默 | ☐ |
| P0-2 | 真的画出来 | 播放中退到桌面 | 屏幕上出现歌词，当前行高亮 | ☐ |
| P0-3 | 自检工具 | 设置 → 歌词 → 「悬浮歌词自检」 | 五项（授权 → 开关 → 服务 → 窗口 → 内容）**全绿**；哪项断了一目了然 | ☐ |

| P0-9 | 暂停表现 | 播放中按暂停 | 「暂停时的悬浮歌词」设置的行为生效（按你选的档位） | ☐ |
| P0-10 | 被杀后恢复 | 播着音乐，用系统「一键清理」清后台 | 后台服务被清后**不应留下僵尸悬浮窗**；重新进入 App 应能恢复 | ☐ |
| P0-11 | 锁屏 / 切应用 | 锁屏、切到微信/相机、回桌面 | 歌词不闪断、不错位；App 内自动隐藏悬浮窗 | ☐ |

> **P1-19 为什么要单独标出来**：v1.1.3 ~ v1.1.11 三个快捷方式**全部**点不动 —— 点击提示
> 「未安装应用」。根因是 `shortcuts.xml` 的 `<intent>` 只写了 `targetClass` 没写
> `targetPackage`，启动器解析不到落点。v1.1.12 改为「只写 action + 在 `MainActivity` 上
> 声明同 action 的 `intent-filter`（隐式解析）」。这类故障**编译期、启动期都无感**，
> 只有真机长按点一下才知道 —— 模拟器上可用
> `adb shell cmd package resolve-activity --brief -a com.luckylearning.windtone.SHORTCUT`
> 先自查（修复前回 `No activity found`，修复后应回 `…/MainActivity`）。

> **P1-19B 为什么也常被漏掉**：v1.1.12 修好"点得动"之后，用户立刻发现**三个入口都只是把应用打开**，
> 一个动作都没执行（v1.1.3 ~ v1.1.12 一直如此，只是之前被"未安装应用"盖住了）。
> 两个独立成因：① 就绪判据在冷启动第一帧就判成"已就绪"，动作被消费时曲库还是空的；
> ② 「打开我的收藏」去 `playlists` 里按 id 找虚拟歌单，而那里**只有自建歌单**，
> 查找必然为空，于是只切了视图 → 落在「歌单」列表页。
> 两者都是"能装能启动、点一下才知道"的类型，所以这一条必须在真机上按三个入口逐个走一遍。

## 附录 A · 真机取证速查

不通过时，下面这些命令比截图和回忆有用得多（`adb` 在项目 `.toolchain/android-sdk/platform-tools/`）。

```bash
# 1) 装 Release 包（把 vX.Y.Z 换成实际版本）
adb install -r WindTone-vX.Y.Z-arm64-v8a.apk

# 2) 抓崩溃 / 异常
adb logcat -d | grep -iE "FATAL|AndroidRuntime|ANR " | tail -40

# 3) 抓播放状态（是否真在播、位置有没有推进）
adb shell dumpsys media_session | grep -E "state=PlaybackState"

# 4) 抓悬浮窗是否真的被系统添加（悬浮歌词看不到时用）
adb shell dumpsys window windows | grep -i "windtone"

# 5) 抓音频流是否在输出（EQ 疑似无效时用）
adb shell dumpsys audio | grep -i "AudioPlaybackConfiguration"

# 6) 应用内：设置 → 关于与诊断 → 「悬浮歌词自检」/「崩溃日志」
```

> 注意：Git Bash 下推送 `/sdcard/...` 需要 `MSYS_NO_PATHCONV=1`，否则路径会被改写成 `PortableGit/sdcard/...`。
> debug 包的包名带后缀：`com.luckylearning.windtone.debug`；Release 包是 `com.luckylearning.windtone`。
