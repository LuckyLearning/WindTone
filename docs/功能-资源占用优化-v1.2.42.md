# 资源占用优化（v1.2.42）

依据：v1.2.40 车机诊断包（宋 L / DiLink5.0）—— VmRSS ~600MB（峰 758）、
libc malloc Private_Dirty ~246MB、封面位图缓存命中 ~0%、悬浮窗可见性重算 919（变化 41）、
无障碍轮询 686 次。

## 本版改动

### 1. 封面解码强制 RGB_565（`CoverRepository`）
- 磁盘 JPEG 命中路径补上 `inPreferredConfig = RGB_565`，并经 `ensureRgb565` 硬收口。
- `createScaledBitmap` 之后再压回 565（多数机型缩放会升成 ARGB_8888）。
- **预期**：同尺寸封面像素内存约减半；位图 LRU 能多留几张，冷启动后命中率应上升。
- **不改**：解码目标边长 / 采样算法；SoftEq 路径不动。

### 2. 悬浮窗 `applyVisibility` 降频副作用（`LyricOverlayService`）
- 仅在「本次真变成显示」时才 `refreshA11yHandleStatus` + `updateHandlesPosition`。
- 歌词推进触发的幂等 apply 不再打 `Settings.Secure`、不再 `updateViewLayout` 侧钮。
- **预期**：诊断包「可见性重算」仍可能高（状态流频率），但主线程 IPC / 布局次数大降。

### 3. `OverlayStateBinder` 跳过无意义 apply
- 可见性未变时不调用 `applyVisibility`（首帧仍强制刷一次，避免默认 VISIBLE 漏藏）。
- **预期**：「可见性重算」计数明显下降（接近真实显隐变化次数）。

### 4. 无障碍：ContentObserver + 更慢轮询
- 监听 `ENABLED_ACCESSIBILITY_SERVICES`，名单变更立刻刷侧钮灯。
- 轮询可见 5s→15s、隐藏 15s→60s（只作厂商漏回调兜底）。
- **预期**：「无障碍轮询」次数约为原来的 1/3～1/10（视悬浮窗显隐占比）。

### 未动（有意）
- **ExoPlayer LoadControl** 仍 30s/120s：车机弱网 / 网盘直链需要；砍缓冲会换来卡顿。
- **SoftEqSpike** 默认关；硬 EQ `HARD_ACTIVE` 路径不改。
- malloc ~246MB 主体仍可能是解码器 / 分配器，位图只是其中一块；本版先收「能证明」的路径。

## 车上怎么对比（装 v1.2.42 后）

1. 冷启动 → 播同一张歌单约 10～15 分钟（含导航切前台，让悬浮窗显隐几次）。
2. 设置 → 关于与诊断 → 导出诊断包，对比：
   - **VmRSS / 峰值**、Java 堆、`BitmapMeter` / 封面缓存命中与占用；
   - **可见性重算 vs 实际变化**（比值应更接近，重算绝对值应降）；
   - **无障碍轮询次数**（同时长应明显少于 686）。
3. 主观：长播不卡、侧钮无障碍灯在系统开关后仍能在约 15s 内变色（或立即，若 Observer 生效）。
