# 封面磁盘命中 / 缓存诊断对照加固

## 背景

`CoverRepository` 已有三级缓存（内存位图 → 磁盘 JPEG → 源解码）与 RGB_565。
车机诊断包里曾出现 cover miss 偏高、磁盘体积堆近重复文件的现象：列表缩略图
随密度/字体在相邻像素间漂移（142/143/144），旧实现按**精确 px** 做磁盘文件名，
冷启动「差 1px」即 miss，并多写近重复 JPEG。

诊断侧原先只报磁盘占用字节，**看不到命中/未中**，无法对照「键设计问题 vs 预算过小」。

## 本轮

| 点 | 做法 |
| --- | --- |
| 分桶键 | `cachePxFor(targetPx)`：`< LARGE_COVER_PX` 步长 32，大图 64；`cover()` 位图键与磁盘文件名共用 |
| 命中计数 | `diskHits` / `diskMisses`（AtomicLong）；`decodeInto` 磁盘命中/未中各 +1 |
| 磁盘体积 | `diskBytesCached` 懒缓存；写盘 / 淘汰 / `clearAll` / `evict` 时 invalidate，避免 `stats()` 每次全目录 stat |
| 诊断对照 | `MemoryProbe` `[内存]` 封面磁盘行追加 hits / miss / 命中率；`mp_cover_disk` 四参 |

## 性能口径

- **降资源**：相邻缩略图共享一档磁盘文件 → 少解码、少近重复 JPEG、冷启命中率可对照提升。
- **降诊断成本**：`diskUsageBytes` 不再每次扫描目录。
- 不增常驻线程 / 大缓存；不碰 SoftEq / 播放内核热路径；磁盘上限仍 50MB + 节流 trim。

## 单测

- `CoverCacheTest`：`缩略图相邻像素收成同一桶` / `大图用 64 步长分桶` / `非法目标像素返回 0`

## 未改

- SoftEq、播放内核、E6、内容库名 i18n（P3）
- 磁盘上限数值、RGB_565、`targetPxFor` 倍率口径（分桶在 target 之后）
